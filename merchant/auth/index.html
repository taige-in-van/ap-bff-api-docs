商户后台 认证 — 前端契约面 (2.3.2)

Download OpenAPI specification:

商户后台 React SPA 消费的认证契约：登录与会话（密码、MFA、微信扫码、代登落地、当前会话、切换当前商户、登出）、忘记密码、注册与邮件链接落地页（邮箱激活、设密链接、确认新登录邮箱、代客建档确认页）。 浏览器持 httpOnly 会话 cookie（登录后 set-cookie），字段类型与校验规则以本 spec 各字段为准。

幂等 / CSRF 口径：

  • 认证类（登录、登出、MFA、扫码）与多步挑战类（找回密码、激活链接、确认新邮箱）按流程语义不挂 Idempotency-Key；注册按注册邮箱去重、不挂。
  • cookieAuth 的非安全方法一律带 X-CSRF-Token；公开端点（security: []）不要求会话、不带。
  • 代客建档确认页三个接口不要求会话，凭请求头 X-Confirmation-Token 里的确认令牌（onboardingConfirmationToken），不带 cookie 凭据、不要求 CSRF；签署与提异议以确认令牌去重，不挂 Idempotency-Key。

登录类公开端点读会话 cookie：login、completeMfaChallenge、initiateWechatLogin、pollWechatLogin、establishImpersonationSession 是公开端点、不要求会话，但会读请求带的会话 cookie 做已登录检查——本浏览器会话仍有效时不处理这次提交、回 409·208042。

登录与会话

登录与会话：密码登录（已启 MFA 转二次校验）、微信扫码登录、当前会话、切换当前商户、登出。

密码登录（邮箱或用户名 + 密码；已启 MFA 则转二次校验）

邮箱或用户名 + 密码认证（client 由服务端注入、前端不传）。未启 MFA 直接建会话（set-cookie）； 已启 MFA 返回 MFA_REQUIRED 和一次性挑战句柄 mfaChallenge（未建会话），再调 completeMfaChallenge。

错误码：

  • 206012 凭据错：密码错、账号不存在、该账号不能登录商户后台（没有商户后台的角色）都返回此码、不区分；受邀但未设密的员工也返回此码。
  • 208029 邮箱未验证。
  • 208027 账号被禁用。
  • 208028 取不到当前商户（规则见下「建会话时的当前商户」），不建会话。
  • 966001 账号因连续登录失败被锁。
  • 409·208042 本浏览器已登录：请求带的会话仍有效时不处理这次提交（不校验凭据、不建新会话、原会话原样保留、不计失败次数、不记登录流水，本次的 rememberMe 不生效），前端进入登录后页面；换号须先登出。
  • 同一登录名（解析不到账号）短时间内失败过多 → 429·906004，稍后再试；默认 15 分钟内 5 次（可配置），与 POS、商户 App 登录共用计数。

各情形的页面处理见 flows。

建会话时的当前商户：在该用户能进入的商户（未删除、未冻结）里，取第一个已激活的（主商户在前，关联商户按创建时间）；没有已激活的就取主商户（首次入驻中或已被拒，被拒的虽不在商户列表里也照取）；都取不到（如主商户已冻结、只剩入驻中的关联商户）→ 208028。不记上次用的商户。二次校验、扫码登录建会话同此规则。

界面语言：建会话时这个账号还没有 locale，就把本次请求 Accept-Language 对应的语言记为它的 locale；已有的不动。二次校验、扫码登录建会话同此规则。

凭代登交接码建代登会话（代登落地页提交）

运营从管理后台代登商户时，管理后台新开窗口打开的落地页地址的 fragment 里带一次性交接码（#code=…）；落地页从 fragment 取出交接码调本接口，成功即建会话（set-cookie），返回同 getCurrentSession 的会话上下文，随后进商户后台首页。

代登会话的规则：

  • 当前商户固定为被代的商户，权限按该商户 Owner 算；会话能进入的商户只有它，切到其他商户按不在商户列表处理（404），页面不显示商户切换。
  • 会话不续期：到期即结束，须回管理后台重新发起。
  • 在线复核、登出与被强制下线同普通会话。

交接码只能用一次，用过即失效；刷新落地页不能重进，须回管理后台重新发起。

错误码：

  • 206019 交接码无效、已用过或已过期。
  • 409·208042 本浏览器已登录商户后台：请求带的会话仍有效时不处理这次提交（不消费交接码、不建会话、原会话原样保留）；须先登出该浏览器的商户后台会话，再回管理后台重新发起。

忘记密码

忘记密码自助重置：邮箱登录名收邮件验证码、用户名登录名用验证器码；重置不改 MFA。

找回密码 — 发起（恒 202，不暴露账号是否存在）

按 loginId 的形态选验证方式：

  • 是合法邮箱格式的按邮箱账号：账号存在则往该邮箱发 6 位验证码。
  • 否则按用户名账号：用验证器（TOTP）里的 6 位码，不发邮件；没开验证器的用户名账号无法自助重置，由 Owner 在成员管理里重设。

恒返 202，账号存在与否响应一致。重发 = 冷却结束后再调本接口，得到新 challengeId，旧码作废。429·906004 为端点 / IP 级限流。

验证码邮件按该账号的界面语言发；账号还没有语言偏好时，用本次请求 Accept-Language 对应的语言。

找回密码 — 验证码 + 新密码一次提交

验证码与新密码一次提交，这是找回流程里唯一的核码点：码正确才消费挑战并改密，该用户所有会话失效，并给本人登录邮箱发密码已修改通知（用户名账号不发）。 只改密码、不改 MFA，开了验证器的账号下次登录仍要验证器码。

不挂幂等键（挑战类）。挑战已被消费后再提交返回 206006。

错误码：

  • 204010 验证码错，次数未超限，可重输（新密码无需重填）。
  • 206006 挑战已过期、已作废或已被消费，须重新发起。
  • 206007 错码次数超限，挑战作废，须重新发起。
error-codes: [204010,206006,206007]
path Parameters
challengeId
required
string (ChallengeId) [ 1 .. 32 ] characters

账号开通

账号开通（公开、无会话）：自助注册与邮箱激活（提交注册建待验证账号并发验证邮件，邮件链接落地页输注册密码后激活，含重发验证邮件）；受邀员工在邀请链接落地页设密激活；员工在确认链接落地页确认 Owner 改的新登录邮箱。都不建会话。

Owner 自助注册（建待验证账号并发验证邮件）

提交注册：建待验证账号（邮箱验证前不能登录）并发验证邮件，邮件投递失败不阻塞注册。

该邮箱已有待验证账号时，用本次提交覆盖上次的密码和资料；不在重发冷却内则作废旧验证链接、发新链接。响应与新建相同。 幂等基准：注册邮箱，不挂 Idempotency-Key。同内容重发即再覆盖一次，结果相同。

限流按来源 IP 与按注册邮箱两个维度，任一命中都返回 429·906004。

本次请求 Accept-Language 对应的语言记为新账号的 locale，验证邮件也用它。

错误码：

  • 968001 该邮箱已被其他账号使用（含邀请中、已停用的账号；别人改登录邮箱时尚未确认的新邮箱不算占用）。

凭邮件里的设密链接设密（落地页提交；不建会话）

校验链接里的一次性令牌并写入新密码。不建会话，成功后回登录页用新密码登录。三种链接共用本接口：

  • 员工邀请链接、代客建档 Owner 的开户设密链接：账号由邀请中激活为 ACTIVE，邮箱同时标为已验证。
  • 运营发出的重置密码链接：账号本就是 ACTIVE，状态不变；设密成功即旧密码失效、该账号所有已登录会话失效。设密前旧密码照常可用。

链接带令牌和该账号的邮箱（?token=…&email=…），邮箱只供页面展示，提交以令牌为准。令牌只在设密成功时消费，之前失败的可用同一令牌重试。

本次请求 Accept-Language 对应的语言记为该账号的 locale（已设过语言的不改）。

错误码：

  • 206009 令牌无效或已过期（含被重发作废）。

代客建档确认页

工作人员代为建档后，Owner 凭确认邮件里的链接免登录核对资料与合同，签署提交或提异议。不建会话。

取代客建档确认页内容（申请资料与合同）

确认页从页面地址的 fragment（#token=…）取确认令牌，放在请求头 X-Confirmation-Token 里调用本页三个接口。本接口返回运营代填的申请资料与待签合同，供 Owner 核对。打开页面、刷新与重复读取都不消费令牌。

资料文件只给文件名、不给访问地址；合同用 contractUrl 预览或下载，地址短时有效，过期后重新读取本接口拿新的。

签署合同并提交入驻申请

Owner 核对无误后签署：手写签名（drawn，带签名图）或键入姓名（typed）。签署成功即令牌失效，系统随后为申请完成开通准备并提交审核；开通准备暂时没做成时签署仍有效、申请留在原状态，由运营完成提交。页面只展示签署完成，不承诺已进入审核；之后再打开链接按无效处理。签署时的姓名、方式、时间与来源网络随签署记录保存。
