商户后台 认证 — 前端契约面 (2.0.0)

Download OpenAPI specification:

商户后台 React SPA 消费的认证契约：登录与会话（密码、MFA、微信扫码、当前会话、切换当前商户、登出）、忘记密码、注册与邮件链接落地页（邮箱激活、邀请设密、确认新登录邮箱）。 浏览器持 httpOnly 会话 cookie（登录后 set-cookie），字段类型与校验规则以本 spec 各字段为准。

幂等 / CSRF 口径：

  • 认证类（登录、登出、MFA、扫码）与多步挑战类（找回密码、激活链接、确认新邮箱）按流程语义不挂 Idempotency-Key；注册按注册邮箱去重、不挂。
  • cookieAuth 的非安全方法一律带 X-CSRF-Token；公开端点（security: []）无会话、不带。

sessions

登录与会话：密码登录（已启 MFA 转二次校验）、微信扫码登录、当前会话、切换当前商户、登出。

密码登录（邮箱或用户名 + 密码；已启 MFA 则转二次校验）

邮箱或用户名 + 密码认证（client 由服务端注入、前端不传）。未启 MFA 直接建会话（set-cookie）； 已启 MFA 返回 MFA_REQUIRED 和一次性挑战句柄 mfaChallenge（未建会话），再调 completeMfaChallenge。

错误码：

  • 206012 凭据错：密码错与账号不存在不区分；受邀但未设密的员工也返回此码。
  • 208029 邮箱未验证。
  • 208027 账号被禁用。
  • 208028 取不到当前商户（规则见下「建会话时的当前商户」），不建会话。
  • 966001 账号因连续登录失败被锁。

各情形的页面处理见 flows。

建会话时的当前商户：在该用户在册、未删除、未冻结的商户里，取第一个已激活的（主商户在前，关联商户按创建时间）；没有已激活的就取主商户（首次入驻中或已被拒，被拒的虽不在商户列表里也照取）；都取不到（如主商户已冻结、只剩入驻中的关联商户）→ 208028。不记上次用的商户。二次校验、扫码登录建会话同此规则。

界面语言：建会话时这个账号还没有 locale，就把本次请求 Accept-Language 对应的语言记为它的 locale；已有的不动。二次校验、扫码登录建会话同此规则。

password-resets

忘记密码自助重置：邮箱登录名收邮件验证码、用户名登录名用验证器码；重置不改 MFA。

找回密码 — 发起（恒 202，不暴露账号是否存在）

按 loginId 的形态选验证方式：

  • 含 @ 按邮箱账号：账号存在则往该邮箱发 6 位验证码。
  • 否则按用户名账号：用验证器（TOTP）里的 6 位码，不发邮件；没开验证器的用户名账号无法自助重置，由 Owner 在成员管理里重设。

恒返 202，账号存在与否响应一致。重发 = 冷却结束后再调本接口，得到新 challengeId，旧码作废。429 为端点 / IP 级限流。

找回密码 — 验证码 + 新密码一次提交

验证码与新密码一次提交，这是找回流程里唯一的核码点：码正确才消费挑战并改密，该用户所有会话失效。 只改密码、不改 MFA，开了验证器的账号下次登录仍要验证器码。

不挂幂等键（挑战类）。挑战已被消费后再提交返回 206006。

错误码：

  • 204010 验证码错，次数未超限，可重输（新密码无需重填）。
  • 206006 挑战已过期、已作废或已被消费，须重新发起。
  • 206007 错码次数超限，挑战作废，须重新发起。
error-codes: [204010,206006,206007]

registrations

账号开通（公开、无会话）：自助注册与邮箱激活（提交注册建待验证账号并发验证邮件，邮件链接落地页输注册密码后激活，含重发验证邮件）；受邀员工在邀请链接落地页设密激活；员工在确认链接落地页确认 Owner 改的新登录邮箱。都不建会话。

Owner 自助注册（建待验证账号并发验证邮件）

提交注册：建待验证账号（邮箱验证前不能登录）并发验证邮件，邮件投递失败不阻塞注册。

该邮箱已有待验证账号时，用本次提交覆盖上次的密码和资料；不在重发冷却内则作废旧验证链接、发新链接。响应与新建相同。

幂等基准：注册邮箱，不挂 Idempotency-Key。同内容重发即再覆盖一次，结果相同。

本次请求 Accept-Language 对应的语言记为新账号的 locale，验证邮件也用它。

错误码：

  • 968001 该邮箱已是可登录账号。

邮箱激活（落地页输注册密码后提交；不建会话）

同时核对邮件链接里的一次性令牌和当前待验证账号的注册密码，两者都对才把账号邮箱标为已验证。不建会话、不下发 cookie。

令牌只在激活成功时消费；密码不对或其他失败都不消费，可用同一令牌重试。已消费的令牌再提交（账号已激活）同样返回 204，不再核对密码。

错误码：

  • 206001 令牌无效、已过期或已被重发作废。
  • 206012 注册密码不对。
  • 206007 密码错误次数达上限，该链接已锁定。

受邀员工设密激活（邀请链接落地页提交；不建会话）

校验邀请链接里的一次性令牌，写入新密码并激活账号，邮箱同时标为已验证。不建会话。

邀请链接带令牌和被邀请的邮箱（?token=…&email=…），邮箱只供页面展示，提交以令牌为准。令牌只在设密成功时消费，之前失败的可用同一令牌重试。

本次请求 Accept-Language 对应的语言记为该账号的 locale。

错误码：

  • 206009 令牌无效或已过期（含被重发作废）。
  • 206010 令牌已用过、该员工已激活；本次提交的新密码未生效。
error-codes: [206009,206010]
header Parameters
Accept-Language
string

页面当前的语言（BCP-47，如 zh-Hans / fr-CA），服务端归到 en / fr / zh 之一，认不出按 en。

员工确认 Owner 改的新登录邮箱（邮件链接落地页提交；不建会话）
