商户后台 订单与退款 — 前端契约面 (2.0.0)

Download OpenAPI specification:

商户后台 React SPA 消费的订单与退款契约：支付订单与退款的列表、详情、收据 PDF、导出，发起退款、撤销审核中的退款、预授权完成，以及按日期范围的收款统计。 浏览器持 httpOnly 会话 cookie，字段类型与校验规则以本 spec 各字段为准。

金额：最小币种单位整数加币种。订单列表行、订单汇总与统计是结算币种；发起退款与退款金额是订单的标价币种。各字段是哪个币种见字段说明。

幂等 / CSRF 口径：

  • 三个命令（发起退款、撤销退款、预授权完成）必带 Idempotency-Key，缺了 → 400。同键同请求体重发返回首次结果，网络重试用同一个键；改了请求体要换新键，沿用旧键 → 409·208005。
  • cookieAuth 的非安全方法一律带 X-CSRF-Token。
  • 当前商户以会话为准、不看请求体；当前商户不可访问时返回 409·208022。

payments

支付订单：列表、汇总与状态计数、导出、详情、收据 PDF，以及发起退款、预授权完成。

支付订单列表

当前商户的支付订单，分页。日期范围必填，服务端不设默认。已成交的行金额是结算币种的成交金额，没成交的是标价金额。

列表含 FAILED 与 REJECTED 两种没收到钱的行；汇总卡不算它们，见 getPaymentSummary。状态 chip 的各项与计数另取 getPaymentCounts。

status
string (PaymentStatus)
Enum: "PAID" "PARTIALLY_REFUNDED" "REFUNDED" "FAILED" "REJECTED" "PREAUTH_HOLDING"

支付订单的商户可见状态：PAID 已收款 · PARTIALLY_REFUNDED 部分退款 · REFUNDED 全额退款 · FAILED 付款失败 · REJECTED 平台未受理 · PREAUTH_HOLDING 预授权挂起。

前三种都是已收款，按已退金额区分；退款受理后又失败的会回退，所以订单可能从 PARTIALLY_REFUNDED 回到 PAID。REJECTED 是建单时被平台拒掉、支付从未发生，与 FAILED（付了但失败）不同。收款过程中的中间状态不进列表。

计入汇总的是 PAID / PARTIALLY_REFUNDED / REFUNDED / PREAUTH_HOLDING 四种。

Payments 页头汇总卡

与 listPayments 用同一组筛选参数、基于同一批订单的合计，金额是商户结算币种（每笔按实际结算金额相加）。

只算收到钱的四种状态：PAID / PARTIALLY_REFUNDED / REFUNDED / PREAUTH_HOLDING。列表还会列出 FAILED / REJECTED，所以 transactions 可能小于列表行数。grossSales 就是这四种状态的行金额之和。

refundAmount 是这批订单至今已退的金额（随订单计入，不按退款发生日），netSales = grossSales − refundAmount。

当前商户最近的支付订单，按创建时间倒序，不限日期。只含收到钱的订单（与 getPaymentSummary 计入汇总的范围相同），FAILED 与 REJECTED 不返回。

行与 listPayments 的行相同。不分页，只返回 items；一笔都没有时为空数组。

支付订单详情

单张订单：列表行的字段，加已退金额、产品形态与关联单据号、客户与付款账户、关联退款、回调信息、换汇信息。不存在或不属于当前商户 404。

关联退款里 type = system_auto 的是平台自动退回的多付款项（重复支付、关单后才到的成功支付），没动商户的账，不计入 refundedAmount。

status = REJECTED 的订单从未发生支付，没有支付方式、通道交易号与付款账户。

发起退款（全额或部分，凭 Refund PIN）

对 refundable 为真的订单发起退款。金额的币种是订单标价币种，须大于 0 且不超过 remainingRefundable。上一笔退款没结束时可以再发起，各占各的额度。

能不能退、还能退多少，以受理时重新校验的结果为准。超过可退余额、订单已不可退、商户退款能力关闭、商品已核销或作废 → 400·204008，不建退款单。

Refund PIN：

  • 不对 → 403·206003；
  • 连续输错被锁 → 423·206004。

201 只表示退款单已建，结果看 status：

  • REVIEWING：等平台审核；
  • CHANNEL_PROCESSING：已送通道；
  • FAILED：账户资金不足，退款没有执行，failureReason 为 INSUFFICIENT_FUNDS。占用的可退额度已放回，可以重新发起。

幂等：带 Idempotency-Key。同键同请求体重发返回首次结果，不会建两笔；同键改了请求体 → 409·208005；同键的上一次提交还在处理 → 409·208011。PIN 不参与幂等比对。

statistics

按日期范围的收款统计：汇总与支付方式占比、本月 / 上月逐日趋势。收款按订单成交的日期计，退款按退款受理的日期计，两者各算各的日子，不按原订单配对；与 getPaymentSummary 不是同一个口径（那边按所筛订单算），两边不要互相核对。

日期范围内的收款、退款、净额与支付方式占比

当前商户在 from 到 to（都含）这段日期里的汇总。日期范围必填，服务端不设默认。

  • grossSales：成交订单的收款额合计。
  • refundAmount：受理的商户退款合计，减去受理后失败回冲的；回冲多于退款的范围内为负。系统自动退款不算。
  • netSales：grossSales − refundAmount，可能为负。
  • distribution：grossSales 按支付方式品牌拆开，各项之和等于 grossSales。

范围内没有交易时三个金额为 0、distribution 为空数组。to 早于 from → 400。

Authorizations:
cookieAuth
query Parameters
from
required
string <date> (LocalDate)
Examples: from=2026-08-01

起始日期（含）。

to
required
string <date> (LocalDate)
Examples: to=2026-08-01

结束日期（含）。

本月或上月的逐日收款额与笔数

当前商户本月或上月每天的收款额与成交笔数，不含退款。哪个月是本月由服务端认定，实际月份在响应的 month 里。

points 每天一项、按日期升序、没有交易的日子金额与笔数为 0：current 从当月 1 日到今天，previous 是上月整月。
