商户后台 资金 — 前端契约面 (2.1.2)

Download OpenAPI specification:

商户后台 React SPA 消费的资金契约：账户余额与退款准备金的充值、取回，结算单与逐笔结算明细，月对账单。 浏览器持 httpOnly 会话 cookie，字段类型与校验规则以本 spec 各字段为准。

金额：最小币种单位整数加币种，都是商户的结算币种。

幂等 / CSRF 口径：

  • 两个资金动作（准备金充值、取回）必带 Idempotency-Key，缺了 → 400。同键同内容重发返回首次结果，不会划两次；改了内容要换新键，沿用旧键 → 409·908003。发验证码不挂幂等键。
  • cookieAuth 的非安全方法一律带 X-CSRF-Token。
  • 当前商户以会话为准、不看请求体；当前商户不可访问时返回 409·208022。

账户余额

账户余额：可结算余额、退款准备金余额、自动补足的最低金额；以及退款准备金的充值（要 Owner 邮箱验证码，可同时改自动补足的最低金额）与取回。

账户余额

当前商户的账户余额、待结算金额、退款准备金与自动补足设置，结算币种。

toSettle 是可结算余额减去商户欠平台的钱，不含预授权挂起中的款项，可能为负。它是下一次结算大约会打出来的金额；手续费在结算时扣的商户，实际到账还要再减手续费。

accountBalance 是余额卡片上的账户余额，等于 toSettle 加上预授权挂起中的款项；挂起款项并在里面、不单列，可能为负。

准备金充值第 1 步：发验证码到 Owner 邮箱

发 6 位码到 Owner 的登录邮箱，返回 challengeId。 本步只发码、不带充值内容；码和内容在第 2 步一起提交。

重新发码会让旧码作废，冷却中 → 429·208013。Owner 账号不可用（已停用、已删除或没有已验证邮箱）→ 409·208056。按挑战流程语义不挂幂等键。

required-privilege: account:reserve:create
error-codes: [208013,208056]
Authorizations:
cookieAuth
header Parameters
X-CSRF-Token
required
string non-empty .*\S.*

CSRF 令牌(double-submit;cookie 会话鉴权的非安全方法[POST/PUT/PATCH/DELETE]必带;缺失/不匹配 → 403 fail-closed)。取值 = 本 BFF 可读伴生 CSRF cookie 的当前值(cookie 名 per-BFF、见该面 cookieAuth 说明;建会话时随会话 cookie 一起下发、同生命周期),每次请求现读、不要缓存。

准备金充值第 2 步：充值与 / 或改自动补足的最低金额

从 Account Balance 向退款准备金充值，和 / 或修改自动补足的最低金额；两项至少给一项，带第 1 步的 challengeId 与验证码。

验证码：

  • 不对 → 400·204010，剩余次数在 context.attemptsRemaining；
  • 已过期，或不是在发起它的同一次登录里提交 → 410·206006；
  • 错太多次被锁 → 423·206007。

以上任一情形，充值与设置都不生效。

200 表示已处理：

  • 给了 topUpAmount 时看 topUp.status：POSTED 已划转；REJECTED 是 Account Balance 不够，没有划转。
  • 给了 minimumAmount 时最低金额已保存，与充值是否成功无关。

最低金额低于平台规定的下限 → 400·204018，当前下限在 context.floorAmount；整次提交不生效。

最低金额只是保存设置。准备金低于最低金额时，平台每天从待结算金额（toSettle）补一次，不够就补到有多少算多少。

幂等：带 Idempotency-Key。比对只看 topUpAmount 与 minimumAmount，不看 otp——验证码输错后重输、网络重试都用原键；同键同内容在验证码核验成功后的回放窗内重发返回首次结果，不会划两次；超出回放窗后按码已用 → 410·206006，须重新发码再提交。改了金额或设置 → 换新键，沿用旧键 → 409·908003；同键的上一次提交还在处理 → 409·908002。

结算单

结算单：列表与导出，每张结算单的逐笔明细与导出。

结算单列表

当前商户的结算单，分页。一张结算单是某个清算日对本商户的一次出款。日期按结算日筛，两个都不传就不按日期筛。

error-codes: []
Authorizations:
cookieAuth
query Parameters
from
string <date> (LocalDate)
Examples: from=2026-08-01

结算日的起始日期（含当日）。不传即不设下界。

to
string <date> (LocalDate)
Examples: to=2026-08-01

结算日的截止日期（含当日）。不传即不设上界。

status
string (SettlementStatus)
Enum: "PENDING" "PROCESSING" "SETTLED" "FAILED" "RETURNED"

结算单状态：PENDING 待出款 · PROCESSING 出款中 · SETTLED 已结算 · FAILED 出款失败 · RETURNED 出款后被银行退回。

FAILED 的结算单会重新出款，状态回到 PENDING。RETURNED 是终态：退回的钱回到 Account Balance，随后面的结算单再出。

pageNum

一张结算单的逐笔明细

归进这张结算单的每一笔资金移动，分页，按发生时间先后排。除收款与退款外，还包括准备金的充值与取回、平台调账、营销账户取现、被退回的出款。

金额都不带符号，算加还是算减由 type 决定。各行按正负把 netAmount 加总，等于结算单的 payoutAmount。
