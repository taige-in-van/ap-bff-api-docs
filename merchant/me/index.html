商户后台 商户实体 — 前端契约面 (2.0.0)

Download OpenAPI specification:

商户后台 React SPA 消费的商户主体资料 / 结算 / Refund PIN / 多商户 / Service Page / 集成 契约。 覆盖 Merchant 主体资料 + BusinessProfile + Refund PIN 凭据 + 结算事前审批 + Service Page 2 层模型（AcceptanceMode / PaymentMethod）。

字段类型以本 spec 为准。

幂等/CSRF 口径:

  • ① 创建类 + 非天然幂等写（Add Merchant / Connect AcceptanceMode / Connect Ecommerce / 创建结算变更请求 / 改 Refund PIN / Forgot PIN 重置 / 改 URL 触发重审）挂 Idempotency-Key——无自然业务单号，或重放不自洽（当前 PIN 已消费、撞待审核请求 → 409），retry 用同键返首次结果;

    天然幂等的纯 PUT/DELETE（改 Business Information / 切当前商户 / 启停 PaymentMethod / Terminal 连接·停用 / Logo）可不挂幂等键;

    OTP 多步挑战按流程语义每次重新校验。

  • ② 非安全方法一律挂 X-CSRF-Token（double-submit，fail-closed）。

  • ③ 当前商户上下文守卫（读写统一）：会话当前商户 = 数据可见范围唯一权威、不信请求体（switchCurrentMerchant 切换更新会话）；目标商户不在可访问集 → 404 反枚举。所有当前商户相关读 + 写携带页面预期 X-Merchant-Context（MerchantContextGuard header param；expected 商户 ID，仅与会话当前商户比对、非选择器）——一致才执行；≠ 会话当前商户 → 409（读不返回错商户、写不执行）：

    • 会话有当前商户、只是与 expected 不同 → 208001（MERCHANT_CONTEXT_CHANGED，context.currentMerchantId 回显）；
    • 会话没有当前商户 → 208022（MERCHANT_NOT_ACCESSIBLE，无可回显者、前端重跑启动链路）。

    前端统一 interceptor 发送 + 处理 409（提示 + 刷新当前商户）。豁免 listMerchants / switchCurrentMerchant / withdrawOnboardingApplication（按 path 选目标、target≠current）/ 全局接口。

  • ④ Idempotency-Key 语义：retry 用同一 key 返回首次结果（retry-safe），区别于 OTP token 的一次性消费（消费后不可重取首次结果）。

  • ⑤ OTP 错误分类（OTP verify 端点 verifySettlementOtp）：

    • 错误但可重试 → 400 204010（剩余尝试数走 context.attemptsRemaining 整数类型——该码必带，见错误码表 requiredContextFields；details 只做请求字段校验红框、不承载剩余次数）;
    • 尝试超限锁定 → 423;
    • 过期 / 已消费 → 410;
    • Resend 冷却 → 429。

profile

BusinessProfile 概览与编辑：Profile 聚合（Header card + 4 section + 资金只读 + Locked 标识）、Business Information 7 可编辑字段直接生效、Logo 上传/移除。Locked 字段服务端强制（绕过 → 403）。

查看 Profile 概览（Header card + 4 section；聚合 BusinessProfile + Merchant + Contact + 资金）

聚合当前选中 ACTIVE 商户的 Profile 概览：Header card（Logo / Trade Name (DBA) / Legal Business Name / Industry • MCC / Merchant ID） + 4 section（Business Information / Settlement / Contact Information / Documents 摘要）。

  • Locked 字段附 locked: true 标识;
  • account_number 掩码仅末 4 位（•••• 5678）;
  • 资金字段（Account Balance / Refund Reserved）为只读展示（无修改入口）;
  • Contact Information 为只读聚合展示、编辑走 owner-contact 端点。

404 仅表示资源不存在 / 不可见，不承载商户状态前置失败。

编辑 Business Information（7 可编辑字段直接生效；Locked 字段 enforce 403）

编辑 ACTIVE 商户 Business Information section 的 7 项可编辑字段（Address / City / Province / Postal Code / Country / Time Zone / Business Phone）， 保存直接生效（无审核）。

任何 7 项 Locked 字段 （Legal Business Name / Trade Name (DBA) / Ownership Type / Registration Number / Referred By / Industry Category / MCC） 出现在请求体即服务端拒绝（403），不持久化、不依赖前端隐藏。

幂等：纯 PUT、天然幂等（同字段集重复提交结果一致），不挂 Idempotency-Key。

改 timeZone 可能被拒：与已出账的历史数据冲突时 → 409 208016， 且整个请求不持久化（含同请求内其他 6 个可编辑字段，需整体重提）； 系统暂时判不出时也返同一个码，按「当前不能改、稍后再试」处理。 未改 timeZone 的请求不会触发这条。

取得 Logo 直传目标（浏览器据此直传，文件不经本接口）

更换 Logo 分两步。

  • 第一步调本接口，用声明值（内容类型 / 大小）换一个直传目标；
  • 第二步由浏览器把文件连同目标中的 fields 一起提交到 action，文件字节不经过本接口； 提交成功后调 POST /account/profile/logo 使其生效。

允许的格式与大小上限见 purpose 的用途表；声明值不合规 → 400 FILE_DECLARATION_REJECTED (204015) 且不签发目标——换一个合规的文件再申请，同一文件重试无用。

非幂等：每次调用产生新 fileId、重试不复用；不挂 Idempotency-Key。

  • 同 Merchant 至多 1 个 PENDING_REVIEW → 已存在则 409（不创建新请求）;

文件是否就位暂时无法判定（上游不可达 / 超时）→ 502 / 504：不必重传，请求内容未变，用原键原样重试。

审核 approve/reject 结果异步更新（不在本 BFF）。
