商户后台 个人账号 — 前端契约面 (2.0.0)

Download OpenAPI specification:

商户后台 React SPA 消费的个人账号契约：登录者本人的资料（昵称、界面语言）、改自己的登录邮箱、账户安全（改密、开启与关闭 MFA）。读「我」走认证契约的 getCurrentSession。 浏览器持 httpOnly 会话 cookie，字段类型与校验规则以本 spec 各字段为准。

幂等 / CSRF 口径：

  • 改密挂 Idempotency-Key；改登录邮箱与开关 MFA 的多步挑战按流程语义不挂；天然幂等的改资料不挂。
  • cookieAuth 的非安全方法一律带 X-CSRF-Token。

登录邮箱

改自己的登录邮箱：身份校验 → 提交新邮箱 → 新邮箱收到的码确认。

改登录邮箱 — 发起（返回身份校验方式）

邮箱账号发起改登录邮箱，返回 challengeId 串起后续步骤。身份校验方式：已启 MFA 用验证器码；未启用旧邮箱的码，本步即发出。

My Profile 和 Business Profile（Owner 本人改 Primary Email）都调本组接口。同一个人的登录邮箱同时只有一笔改动在途，含 Owner 在成员管理里给员工发起的：新发起顶掉上一笔，上一笔再提交返回 206006。用户名账号不能自助改，返回 409·968006。

账户安全

账户安全：改密、开启与关闭 MFA（验证器）。退款 PIN 在商户资料契约。

登录态改密（用当前密码校验；其他会话失效、当前保留）

用当前密码校验后改为新密码，不接受验证器码或邮箱码代替。改密后该用户其他会话失效，当前会话保留；给本人登录邮箱发密码已修改通知（用户名账号没有邮箱，不发）。

幂等基准：Idempotency-Key。同键同请求体重发返回 204；同键改请求体返回 409·908003。

错误码：

  • 206011 当前密码错（会话仍有效，不计入登录锁定）。
  • 908003 同一幂等键被用于不同的请求体。
required-privilege: session
error-codes: [206011]
Authorizations:
cookieAuth
header Parameters
Idempotency-Key
required
string non-empty .*\S.*

幂等键(写接口;两段命中语义——同键同 payload → 返首次结果 / 同键异 payload → 拒 409·908003;同键首次请求还在处理 → 409·908002。缺键 → 400·904002)

X-CSRF-Token
required
string non-empty .*\S.*

CSRF 令牌(double-submit;cookie 会话鉴权的非安全方法[POST/PUT/PATCH/DELETE]必带;缺失/不匹配 → 403 fail-closed)。取值 = 本 BFF 可读伴生 CSRF cookie 的当前值(cookie 名 per-BFF、见该面 cookieAuth 说明;建会话时随会话 cookie 一起下发、同生命周期),每次请求现读、不要缓存。

关闭 MFA（输验证器码）

输当前验证器码后关闭 MFA，删除密钥。

错误码：

  • 206011 验证器码错，MFA 保持开启。
required-privilege: session
error-codes: [206011]
Authorizations:
cookieAuth
header Parameters
X-CSRF-Token
required
string non-empty .*\S.*

CSRF 令牌(double-submit;cookie 会话鉴权的非安全方法[POST/PUT/PATCH/DELETE]必带;缺失/不匹配 → 403 fail-closed)。取值 = 本 BFF 可读伴生 CSRF cookie 的当前值(cookie 名 per-BFF、见该面 cookieAuth 说明;建会话时随会话 cookie 一起下发、同生命周期),每次请求现读、不要缓存。

Request Body schema: application/json
required
code
required
string (OtpCode) ^[0-9]{6}$

6 位验证码；收哪一种码（邮箱码、验证器码）见各接口。

Responses

商户后台 BFF（浏览器经边缘网关 merchant.* 可达；cookieAuth 会话 + CSRF）

/api/merchant/v1/me/security/mfa/deactivation
