Download OpenAPI specification:

Dashboard 数据洞察前端契约：概览（KPI 卡 Gross / Refund / Net / To Settle + Payment Distribution 支付方式分布， 右上角全局时间窗驱动、默认今日）+ 趋势（Transaction Volume + Orders 双序列，自带本月 / 上月切换、独立于全局时间窗）。 数据洞察为只读呈现：服务端按所选时间窗返回聚合结果（Net = Gross − Refund 由服务端算出、可为负）， FE 只从各分片金额派生展示百分比、不自行汇总；To Settle 与账户账务与清结算页同源、口径一致。 金额一律商户唯一结算币种（最小币种单位整数字符串）；日期为商户营业日（BusinessDate —— 在业务事实达成时固化的归属日标签， 按字面值匹配、不按当前时区切桶；改商户时区 / 日切时刻不改变历史各日数值）。 merchant scope 从会话取、不信请求体；全部 op merchant-current-scoped，均挂 MerchantContextGuard（stale-tab 守卫，无豁免）。 全部端点前置 Merchant.status = ACTIVE 门禁（非 ACTIVE → 403；Dashboard 仅已激活商户可达）。 区块降级不整页失败：某区块取数超时 / 失败 → 该区块 status=unavailable（HTTP 仍 200 返回），其余区块照常渲染（区块隔离）。 字段类型以本 spec 为准。

insight

Dashboard 数据洞察：概览（KPI + 分布，全局时间窗驱动）+ 趋势（双序列，本月 / 上月独立切换）。

读 Dashboard 概览（KPI 卡 + Payment Distribution；全局时间窗驱动）

返回当前商户 Dashboard 概览区块，受右上角全局时间窗（from / to 商户营业日区间、闭区间；均省略 = 今日，相对日期目标由服务端按该商户当前生效配置求出）驱动： KPI 卡 —— Gross Sales / Refund Amount / Net Sales（= Gross − Refund）按窗聚合（结算币种）+ To Settle 即时态（当前待结算派生值、不随时间窗变化）； Payment Distribution —— 窗内成功收款按支付方式分布（金额 + 归并「其他」；占比由 FE 从金额派生）。 Refund Amount 按退款申请时间入窗、排除系统自动退款。 区块降级（分组判别）：Gross / Refund / Net 为一组、三项整体判别（同时 available 或同时 unavailable）； To Settle 与 Payment Distribution 各自独立判别——某项取数超时 / 失败 → 对应组 / 块 unavailable（非 0）、其余照常渲染。 「窗内无交易」= 空态（Gross / Refund / Net = available 且金额为 "0"、分布 available 且 slices 为空），与 unavailable 语义分离。 400：参数校验（from / to 未成对 / 格式错 / to < from）；时间窗跨度超上限（含首尾 > 366 自然日，默认值、可配置） → 204012 WINDOW_RANGE_TOO_LARGE（缩小日期范围后重试，不截断、不降级取部分窗）。

query Parameters
from
string <date> (BusinessDate)
Examples: from=2026-05-19

时间窗起始（商户营业日，闭区间左端；from / to 须同时提供或同时省略，省略 = 今日；to < from → 400；起止跨度〔含首尾〕> 366 自然日〔默认值、可配置〕→ 400 WINDOW_RANGE_TOO_LARGE）。按固化的归属日标签字面值匹配；前端不做时区换算。

to
string <date> (BusinessDate)
Examples: to=2026-05-19

时间窗结束（商户营业日，闭区间右端；与 from 成对）。

header Parameters
X-Merchant-Context
required
string non-empty

stale-tab 一致性守卫（读写统一）：页面预期的当前商户 ID。与会话当前商户比对，一致才执行； 不一致 → 409 MerchantBffConflict（code 208001、MERCHANT_CONTEXT_CHANGED）——读不返回错商户数据、写不执行，响应 context.currentMerchantId 回显服务端当前商户供前端直接 re-sync。 挂在所有依赖当前商户的读 + 写接口；前端统一 interceptor 发送 + 处理 409（提示并刷新当前商户）。 豁免：listMerchants（返回 currentMerchantId 的 re-sync 入口）、switchCurrentMerchant（切换当前商户）、withdrawOnboardingApplication（目标由 path 指定、与当前商户无关）、以及不依赖当前商户的接口。

读 Transaction Volume 趋势（Volume + Orders 双序列；本月 / 上月独立切换）

返回当前商户交易趋势双序列，按所选月份（month=current|previous，默认 current；本月 / 上月的目标范围由服务端在查询时按该商户当前生效配置求出）、按固化的商户营业日标签逐日聚合： Transaction Volume = 成功收款交易额（结算币种）、Orders = 成功订单 / 交易笔数。 趋势图时间控件独立——仅受本端点 month 管辖，不受 /insights/overview 全局时间窗影响（两控件不合并）；范围固定本月 / 上月两档。 「所选月份内无交易」= 空态（available 且 points 为空，FE 按零基线渲染），与取数失败 unavailable 语义分离。 points 仅含有数据的日；缺数据日由 FE 补零基线。

Authorizations:
cookieAuth
query Parameters
month
string
Default: "current"
Enum: "current" "previous"

趋势月份档（本月 / 上月二选一，默认本月）。封闭枚举；范围固定、不接受任意区间、不随全局时间窗变化。
