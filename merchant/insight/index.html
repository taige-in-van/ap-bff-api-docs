Download OpenAPI specification:

Dashboard 数据洞察前端契约：概览（KPI 卡 Gross / Refund / Net / To Settle + Payment Distribution 支付方式分布， 右上角全局时间窗驱动、起止必填）+ 趋势（Transaction Volume + Orders 双序列，自带本月 / 上月切换、独立于全局时间窗）。 数据洞察为只读呈现：服务端按所选时间窗返回聚合结果（Net = Gross − Refund 由服务端算出、可为负）， FE 只从各分片金额派生展示百分比、不自行汇总；To Settle 与账户账务与清结算页同源、口径一致。 金额一律商户唯一结算币种（最小币种单位整数字符串）；日期一律 LocalDate。 merchant scope 从会话取、不信请求体；全部 op merchant-current-scoped，均挂 MerchantContextGuard（stale-tab 守卫，无豁免）。 区块降级不整页失败：某区块取数超时 / 失败 → 该区块 status=unavailable（HTTP 仍 200 返回），其余区块照常渲染（区块隔离）。 保证只在单个响应内成立：同一响应里「各分片金额合计 = 该响应的 Gross Sales」必然相等；但概览与趋势是两次独立取数， 两者的数字可能来自不同时刻，不保证同刻一致——不要拿趋势各日合计去核对概览的 Gross、也不要据此提示用户数据异常。 字段类型以本 spec 为准。

insight

Dashboard 数据洞察：概览（KPI + 分布，全局时间窗驱动）+ 趋势（双序列，本月 / 上月独立切换）。

读 Dashboard 概览（KPI 卡 + Payment Distribution；全局时间窗驱动）

返回当前商户 Dashboard 概览区块，受右上角全局时间窗（from / to 闭区间、两者必填；服务端不解析「今日」这类相对语义——初始展示哪一段由客户端自己算出并作为具体日期发出）驱动： KPI 卡 —— Gross Sales / Refund Amount / Net Sales（= Gross − Refund）按窗聚合（结算币种）+ To Settle 即时态（当前待结算派生值、不随时间窗变化）； Payment Distribution —— 窗内成功收款按支付方式分布（金额 + 归并「其他」；占比由 FE 从金额派生）。 三项 KPI 金额均为服务端返回的结算币种金额；**Refund Amount / Net Sales 可能为负——不表示口径错误， FE 按有符号金额原样渲染、不得截为 0；Net Sales 直接用服务端返回值、FE 不自行相减。 需逐笔核对的场景走交易 / 退款明细列表，但交易管理页的同名字段是按那一页的筛选条件算出的另一个量、与本页口径不同，两页数字不可互相核对或推导。 区块降级（分组判别）：Gross / Refund / Net 为一组、三项整体判别（同时 available 或同时 unavailable）； To Settle 与 Payment Distribution 各自独立判别——某项取数超时 / 失败 → 对应组 / 块 unavailable（非 0**）、其余照常渲染。 「窗内无交易」= 空态（Gross / Refund / Net = available 且金额为 "0"、分布 available 且 slices 为空），与 unavailable 语义分离。 400：参数校验（from / to 未成对 / 格式错 / to < from）；时间窗跨度超上限（含首尾 > 366 自然日，默认值、可配置） → 204012 WINDOW_RANGE_TOO_LARGE（缩小日期范围后重试，不截断、不降级取部分窗）。

query Parameters
from
required
string <date> (LocalDate)

时间窗起始（闭区间左端）。必填——页面右上角恒有时间窗控件、初始展示哪一段（今日）由客户端决定并发出，服务端不代为求「今日」。**起止跨度〔含首尾〕> 366 自然日〔可配置〕→ 400 WINDOW_RANGE_TOO_LARGE**（本模块特有上限）。

to
required
string <date> (LocalDate)
Examples: to=2026-05-19

时间窗结束（闭区间右端；与 from 成对必填）。

header Parameters
X-Merchant-Context
required
string non-empty

stale-tab 一致性守卫（读写统一）：页面预期的当前商户 ID。与会话当前商户比对，一致才执行；不一致时读不返回错商户数据、写不执行，并按下面两种情形二分： ① 会话有当前商户、只是与 expected 不同 → 409 · 208001（MERCHANT_CONTEXT_CHANGED），响应 context.currentMerchantId 回显服务端当前商户供前端直接 re-sync； ② 会话没有当前商户（无可回显者）→ 409 · 208022（MERCHANT_NOT_ACCESSIBLE），前端重跑启动链路按 routeTo 分流（见 API 基础约定「merchant scope + stale-tab 守卫」）。 挂在所有依赖当前商户的读 + 写接口；前端统一 interceptor 发送 + 处理 409（提示并刷新当前商户）。 豁免：不依赖「当前商户」的接口——当前商户的 re-sync / 切换入口本身，以及目标由 path 直接指定、与当前商户无关的接口。 某个接口挂没挂本 header，看该接口的 parameters 即可（挂了就是必带）。

读 Transaction Volume 趋势（Volume + Orders 双序列；本月 / 上月独立切换）

返回当前商户交易趋势双序列，按所选月份（month=current|previous，必填、无默认档；只提供这两档、不接受任意区间，实际日期范围由服务端求出并经 window 回显）逐日聚合： Transaction Volume = 成功收款交易额（结算币种）、Orders = 成功订单 / 交易笔数。 两序列同轴（均为收款类指标），不含退款——退款有自己的入窗轴、只出现在概览的 Refund Amount。 趋势图时间控件独立——仅受本端点 month 管辖，不受 /insights/overview 全局时间窗影响（两控件不合并）；范围固定本月 / 上月两档。 「所选月份内无交易」= 空态（available 且 points 为空，FE 按零基线渲染），与取数失败 unavailable 语义分离。 points 仅含有数据的日；缺数据日由 FE 补零基线。

error-codes: [208001]
Authorizations:
cookieAuth
query Parameters
month
required
string
Enum: "current" "previous"

趋势月份档（本月 / 上月二选一）。必填——初始展示哪一档由客户端决定。封闭枚举；范围固定、不接受任意区间、不随全局时间窗变化。⚠️ 哪个月是 current 由服务端认定（客户端不要自己按本地时间推算），实际日期范围见响应的 window。
