商户后台 设备 — 前端契约面 (2.0.0)

Download OpenAPI specification:

商户后台 React SPA 消费的设备契约：设备列表与状态计数、绑定（预登记，设备首次登录后激活）、停用 / 启用、解绑，以及每台设备的日志（三类，可导出）。 浏览器持 httpOnly 会话 cookie，字段类型与校验规则以本 spec 各字段为准。

幂等 / CSRF 口径：

  • 绑定设备挂 Idempotency-Key，同一次提交的网络重试用同键返回首次结果；天然幂等的纯 PUT / DELETE 不挂。
  • cookieAuth 的非安全方法一律带 X-CSRF-Token。
  • 当前商户以会话为准、不看请求体；当前商户不可访问时返回 409·208022。

设备

设备：列表与状态计数、绑定、停用 / 启用、解绑，以及每台设备的日志。

设备列表

商户在册的设备（已解绑的不在内），分页。顶部状态 chip 的各项与计数另取 getDeviceCounts；Filters 面板的门店候选取 listDeviceStores，来源与状态是固定枚举。

绑定新设备

预登记一台硬件 POS：来源、型号、序列号、门店四项。建成后状态是 PENDING_ACTIVATION，不签发凭据、没有激活码；这台设备首次登录时按序列号对上本条记录即激活。

本商户名下已有同一序列号的在册设备 → 409·208021。判重只在本商户名下做：别的商户登记过同一串不在这里拦，等设备真正登录时才判。

幂等：带 Idempotency-Key，重放同键返首次结果、payload 冲突 → 409·908003；同键的上一次提交还在处理 → 409·908002。

required-privilege: products:device:manage
error-codes: [208021]
Authorizations:
cookieAuth
header Parameters
X-CSRF-Token
required
string non-empty .*\S.*

CSRF 令牌(double-submit;cookie 会话鉴权的非安全方法[POST/PUT/PATCH/DELETE]必带;缺失/不匹配 → 403 fail-closed)。取值 = 本 BFF 可读伴生 CSRF cookie 的当前值(cookie 名 per-BFF、见该面 cookieAuth 说明;建会话时随会话 cookie 一起下发、同生命周期),每次请求现读、不要缓存。

Idempotency-Key
required
string non-empty .*\S.*

幂等键(写接口;两段命中语义——同键同 payload → 返首次结果 / 同键异 payload → 拒 409·908003;同键首次请求还在处理 → 409·908002。缺键 → 400·904002)

停用或启用设备

enabled: false 停用，设备立即不能收款；enabled: true 恢复。目标态与当前一致时照样 204。

启用后 status 是 ONLINE 还是 OFFLINE，看有没有操作员在这台设备上登录使用；平台不主动探测。

还没激活的设备不能停用或启用 → 409·208003。
