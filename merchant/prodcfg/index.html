商户后台 收单配置 — 前端契约面 (1.1.0)

Download OpenAPI specification:

收单配置前端契约：

  • Store QR 展示变体（二维码图形前端渲染）、
  • 收款页设置（PaymentPageSettings + TipConfiguration）、
  • 账单码（Invoice，列表 / 详情 / 创建 / 作废 / 已支付隐藏）、
  • 支付链接（PaymentLink 全部 per-link 配置〔销售内容/生命周期/Policies/Buyer Info〕、创建 / 编辑 / 启停 / 删除 / giftcard 库存只读 / Redemptions 只读 / Transactions 只读）、
  • 设备（列表 / 详情 + 绑定/解绑/启停）、
  • 设备日志、
  • 商户级订单配置（Order Expiry / Customer Service Fee）、
  • POS 小票内容。

字段类型以本 spec 为准。

merchant scope 从会话取、不信请求体；merchant-current-scoped 读写挂 MerchantContextGuard（stale-tab 守卫）。

store-qr

店铺码展示变体（含各变体二维码承载原文；二维码图形由前端渲染，无图片端点）。

读店铺码展示变体（主 QR + 可用变体）

返回当前商户店铺码可展示的变体集（按已开通币种 / QR type / 通道条件显隐；UnionPay QRC 变体需 UPI 通道启用）。 第 1 项就是服务端已选定的主变体——通常是主结算币种的 Standard 码，该组合不可用时服务端会另选一个； 照第 1 项渲染主位即可、不要自己挑，其余按序进「More」。 展示变体随商户可受理方式集变化。

stale-tab 一致性守卫（读写统一）：页面预期的当前商户 ID。与会话当前商户比对，一致才执行；不一致时读不返回错商户数据、写不执行，并按下面两种情形二分：

  • ① 会话有当前商户、只是与 expected 不同 → 409 · 208001（MERCHANT_CONTEXT_CHANGED），响应 context.currentMerchantId 回显服务端当前商户供前端直接 re-sync；

挂在所有依赖当前商户的读 + 写接口；前端统一 interceptor 发送 + 处理 409（提示并刷新当前商户）。

豁免：不依赖「当前商户」的接口——当前商户的 re-sync / 切换入口本身，以及目标由 path 直接指定、与当前商户无关的接口。

保存收款页设置 + 小费配置（两组共同成功 / 失败）

保存 PaymentPageSettings + TipConfiguration（两组同一次提交、共同成功 / 失败，不部分生效）。

支付方式集保存前经受理校验（须为该商户当前可受理方式）—— 不通过 → 409 PAYMENT_METHOD_NOT_ACCEPTABLE；空集 → 400 PAYMENT_METHOD_SELECTION_EMPTY。

Logo 先经 createPaymentPageLogoUploadTarget 取直传目标、由浏览器直传对象存储，再以其 fileId 作 logoRef 提交；保存时该文件才正式归属本设置。

  • 所引文件确定未就位（直传未完成 / 被存储端拒收）→ 400 FILE_NOT_IN_PLACE (204014)，整次保存被拒、两组都不生效。 该码是终态、不可原样重试——须重新取直传目标（得到新 fileId）、重新直传，再用新引用保存；不要向原目标补传（直传目标是一次性的，提交失败即作废）。
  • 暂时判不出（上游不可达 / 超时）→ 502 / 504：不必重传，原样重试本请求。

logoUrl 只出不入、不要提交。天然幂等 PUT（同 payload 重放一致）。

采集项提交的是保留下来的完整键列表（payerInputKeys）——见该字段说明。 缺必填项或自撰标题撞上系统项的键 → 409 PRODCFG_PAYMENT_PAGE_INPUTS_INVALID (208030)，整次保存被拒。 本商户第一次保存本设置时，服务端会把该收的系统项（姓名 / 手机号一类）填进配置里； 此后系统侧新增的项不会追加进已有配置，这份列表就是这个商户收款页的真相。

取得收款页 Logo 直传目标（浏览器据此直传，文件不经本接口）

上传分两步。

  • 第一步调本接口，用声明值（用途 / 文件名 / 内容类型 / 大小）换一个直传目标；
  • 第二步由浏览器把文件连同目标中的 fields 一起提交到 action，文件字节不经过本接口。

允许的格式与大小上限见 purpose 的用途表；声明值不合规 → 400 FILE_DECLARATION_REJECTED (204015) 且不签发目标——换一个合规的文件再申请，同一文件重试无用。

返回的 fileId 即 savePaymentPageSettings 所用的 logoRef——该文件在保存收款页设置时才正式归属它。

非幂等：每次调用产生新 fileId、重试不复用；不挂 Idempotency-Key。

创建支付链接（giftcard/product/ticket）

创建支付链接（按 type 选定 giftcard / product / ticket 之一，并携带对应的内容子对象）→ 建销售实例（status=ACTIVE）+ 返回链接 URL（paymentUrl）；收款 QR 图片不在本响应内，走 downloadPaymentLinkQr 取 PNG。

含 Policies（继承商户级共享默认的快照）与 Buyer / Recipient Information（以 getPaymentLinkCreateConfig 的 default*〔系统级默认〕 为起点、固化进本链接自己的快照，此后改本链接不回写任何共享默认）。

  • currency × methods 组合校验：校验所选方式均支持该标价币种；方式不在该产品候选集内或不支持该币种 → 409 PAYMENT_METHOD_NOT_ACCEPTABLE (208007)；空方式 → 400 PAYMENT_METHOD_SELECTION_EMPTY。
  • 内容币种一致：所有内容价格（denomination / product price / ticket tier price）及 bonus 币种须 = 顶层 currency，不一致 → 400 CONTENT_CURRENCY_MISMATCH (204006)（schema 不强约、服务端校验）。
  • 礼卡内容规则（type=giftcard）：核销规则仅兑换券模式适用 / 赠卡条款为自定义时赠卡备注必填 / 活动截止日不得早于今天 —— 任一不满足拒绝保存 → 400 GIFTCARD_CONTENT_INVALID (204013)（逐字段明细走响应体字段错误）。

素材（Banner / 品牌 Logo）可在本步一并带上：先调 createPaymentLinkAssetUploadTarget 取目标（不需要链接已存在）、浏览器直传，再把得到的 fileId 作 bannerRef / brandLogoRef 随本请求提交；也可以留空、建好后经 updatePaymentLink 再加。

  • 所引文件确定未就位（直传未完成 / 被存储端拒收）→ 400 FILE_NOT_IN_PLACE (204014)，链接不创建。 该码是终态、不可原样重试——须重新取直传目标（得到新 fileId）、重新直传，再用新引用提交；不要向原目标补传（直传目标是一次性的，提交失败即作废）。 ⚠️ 换了 fileId 就是换了请求体，必须同时换新 Idempotency-Key；沿用旧键提交新内容 → 409·208005。
  • 暂时判不出（上游不可达 / 超时）→ 502 / 504：不必重传，用原键原样重试。

幂等：带 Idempotency-Key，重放同键返首次结果、payload 冲突 → 409 IDEMPOTENCY_PAYLOAD_CONFLICT (208005)。

编辑支付链接配置

编辑配置段（Name / Currency / 类型内容 / Payment methods / Buyer Information / Banner / giftcard meta）。

type 须与该链接现有类型一致（链接类型创建后不可变更），它只用于选定内容子对象、不构成改动。

卖出去之后照样能改——名称、售价、销售窗口、活动信息、币种都可以改，不会因为这条链接已经有订单就锁住。 已成交的订单不受影响：它在下单那一刻就把自己买的东西（名称 / 单价 / 数量 / 金额 / 币种 / 活动与品牌信息） 抄了一份存着，之后链接怎么改都不动它。所以卖出一单后发现标题有错别字，直接改就行。 唯一改不了的是礼卡的履约模式，那是创建时就定死的、跟卖没卖过无关（见下）。

⚠️ 改商品 / 票档 / 面值档时，每一项要把详情里读到的 itemId 原样带回——带回 = 改这一项， 不带 = 新增一项，没带回的既有项按下架处理。漏带 itemId 不会报错，但会被当成 「下架旧的、另加一个新的」：新项从零开始卖，旧项的销量与在途订单留在下架的那一项上。 改可售上限还有个下界——不能低于该项的 committedQuantity （409 PRODCFG_ITEM_LIMIT_BELOW_COMMITTED 208031，响应里带上那个数）； 带了不属于本链接的 itemId → 409 PRODCFG_ITEM_UNKNOWN 208032，整次保存被拒。

方式收窄 + currency × methods 组合校验同 createPaymentLink——单改 Currency 校验已有 Methods、单改 Methods 校验现 Currency（任一不兼容 → 409 PAYMENT_METHOD_NOT_ACCEPTABLE 208007）；内容币种须 = 顶层 currency（不一致 → 400 CONTENT_CURRENCY_MISMATCH 204006）。 礼卡内容规则同 createPaymentLink（→ 400 GIFTCARD_CONTENT_INVALID 204013）；履约模式创建后不可变更——请求携带与已存实例不同的 fulfillmentMode → 409 GIFTCARD_FULFILLMENT_MODE_IMMUTABLE (208017)（该字段本就不应可编辑，前端不提供入口）。

素材引用在本步生效（bannerRef / brandLogoRef，取自 createPaymentLinkAssetUploadTarget）：所引文件确定未就位（直传未完成 / 被存储端拒收）→ 400 FILE_NOT_IN_PLACE (204014)，整次编辑不生效。 该码是终态、不可原样重试——须重新取直传目标（得到新 fileId）、重新直传，再用新引用提交；不要向原目标补传（直传目标是一次性的，提交失败即作废）。

暂时判不出（上游不可达 / 超时）→ 502 / 504：不必重传，原样重试本请求。
