本机前端怎么连（必须走 Vite proxy）

会话靠 httpOnly cookie __Host-msession，外加 CSRF 伴生 cookie __Host-mcsrf，都是 SameSite=Lax：浏览器跨站请求不会带上它们，后端也不开 CORS。所以本机前端要让浏览器只看到 localhost，由 Vite 转发：

// vite.config.ts
export default defineConfig({
  server: {
    proxy: {
      '/api/merchant/v1': {
        target: 'https://mer26-test.hqwu.io',
        changeOrigin: true,
      },
    },
  },
})

代码里用相对路径 /api/merchant/v1/... 发请求即可。

  • cookie 带 Secure、不带 Domain，会落在 localhost 上。Chrome / Firefox 把 http://localhost 视为安全上下文，可以直接用；Safari 不行：换浏览器，或给 Vite 开 https（如 @vitejs/plugin-basic-ssl）。
  • 不要改写 cookie 的 domain / path（不需要 cookieDomainRewrite）。

CSRF

  • 非安全方法（POST / PUT / PATCH / DELETE）带请求头 X-CSRF-Token，值 = cookie __Host-mcsrf（前端可读），每次现读、不要缓存。
  • 未登录即可调的 POST（登录、MFA 校验等）不需要。
  • 缺失或不匹配 → 403，错误码 906002；会话失效 → 401，错误码 906001。

细则见 API 基础约定「鉴权与 CSRF」。

自助注册

  • 注册只联调到「激活后能登录」为止：新注册的账号登录后进入驻向导会失败（入驻接口尚未部署）。
  • 邮件不真发，统一进 Mailpit：test 是 https://mailpit26-test.hqwu.io/（dev 是 https://mailpit26-dev.hqwu.io/）。
  • 激活链接打开的是 http://localhost:5173/verify-email#token=…（本机 Vite 默认端口）。你的 Vite 端口不是 5173 时告诉后端改。

扫码登录

  • 轮询要串行：上一次 pollWechatLogin 的响应回来后再发下一次，不要用定时器并发发；重叠的轮询可能让刚建立的登录失效。（flows 扫码登录一节有同样说明。）
  • 轮询 status：WAITING 显示二维码；SCANNED 换成「扫码成功，请在手机上确认」，扫码人被拒时也停在这里直到过期；EXPIRED（过期或手机上取消）自动重新调 initiateWechatLogin 换新码；ESTABLISHED 响应已带会话 cookie。
  • 手机微信里打开的「微信确认页」在独立主机的根路径（test 是 https://wx26-test.hqwu.io/，dev 是 https://wx26-dev.hqwu.io/），与 wechat 面 /identity/wechat/v1 同源。文件（图片、PDF 等）的下载地址在 https://file26-test.hqwu.io/（dev 为 file26-dev）下，由接口返回，前端不用另配。
  • 微信号要先绑定到测试账号才能扫码登录，而绑定接口尚未部署：先用要用的微信扫一次（手机会提示未绑定），把要绑的测试账号和环境（test / dev）告诉后端，后端补上绑定后再扫即可。两个环境的绑定各自独立。

须知

  • 数据会保留：后端部署不再清库，数据模型变化走增量迁移，部署前自动备份数据库。确需清库的个别情况会提前告知。
  • test 的发布：后端择时发布，每次在飞书群发「test 联调环境已更新」，附本次更新内容。dev 部署不发通知。
  • test 跑在云主机上；dev 跑在后端开发机上，偶尔不可达时请直接联系后端。
