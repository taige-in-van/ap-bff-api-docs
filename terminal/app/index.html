商户 App — 终端面契约 (1.0.0)

Download OpenAPI specification:

现网已安装的商户手机 App（iOS 与 Android 版）调用的接口。地址、请求头、请求体与响应的形状都与现网一致，端不需要升级。

域名

  • 多数接口发往 pay 域名（https://pay.example.ca/api/v1.0/app）。
  • 扫码收款等少数接口发往 cashier 域名（https://cashier.example.ca/api/v1.0/app），这些接口在各自的 servers 里标明。
  • 美元区商户用 .com 域名（pay.example.com、cashier.example.com），接口相同。

凭据

  • 登录（signIn）不带凭据；旧版找回密码入口在认证前就地回 400，也不要求凭据。
  • signIn 返回令牌 token，是一个不透明的字符串。此后每个请求把它原样放进 Authorization 头，不加 Bearer 前缀；registerPushToken 这一条现网带着 Bearer 前缀，两种写法服务端都接受。
  • 每个请求另带 devCid 头，值是 App 内置的固定值。
  • 另接受 version（App 版本号）与 Accept-Language（App 当前语言），都不是必需的。
  • 令牌从登录时刻起默认 69 天有效（可配置），请求不会延长它，到期须重新登录。切换商户不换令牌。

令牌在下列情况失效，失效后须重新登录：

  • 退出登录（signOut）。
  • 同一部手机再次登录（按这部手机算，不论账号与商户），上一次登录得到的令牌失效。
  • 该账号修改了登录密码（任何入口）：发起修改的那一处保持登录，该账号其他设备与会话上的登录失效；用 changePassword 改的，这部手机的令牌照常可用。
  • 该账号经找回密码重置了登录密码：该账号所有设备上的登录都失效。
  • 该账号被停用，或被移出商户。
  • 这部手机在该商户下的设备被停用或解绑。
  • 商户被冻结。

同一账号可以同时在多部手机上登录，互不影响。

响应外壳

  • 成功响应都包一层 { status, message, data, timestamp, traceId }，status 为 200，内容在 data；没有内容时 data 为 null。例外：releasePreauth 成功时响应体为空，downloadPaymentReceipt、downloadRefundReceipt、downloadMonthlyStatement 成功时响应体是 PDF 文件本身，都不套这一层；它们失败时照常。
  • 失败响应的 HTTP 状态不是 2xx，响应体是 { status, message, data, timestamp, traceId, code }：status 与 HTTP 状态相同，message 是失败原因的文案，data 为 null，code 是整数错误码。
  • 订单详情与退款详情照现网，没有值的键给 null；其余接口没有值时不返回该键。

状态码

失败只用下面三档，其余 4xx 不使用。

HTTP 状态 情形
403 需要重新登录：令牌无效或已失效、缺凭据头、设备被停用、当前商户被冻结。切换商户时也是这样
400 登录被拒（含上一行的设备、商户原因在登录时仍然存在）；切换商户的目标不可访问，或这部手机在目标商户下的设备被停用；权限不足、参数不对、状态不允许、操作太频繁等业务性拒绝
5xx 服务端故障

403 的 code，每个受保护的接口都可能返回，各接口说明里不再重复：

  • 206014 令牌无效或已失效，或没带凭据头。
  • 208033 这部手机在当前商户下的设备已被停用。
  • 208028 当前商户已被冻结。

400 的 code 见各接口说明；说明里没点名的（参数不合法、操作太频繁等）按 message 处理即可。失败响应可能另带 context，内容与登记该码的码表所写相同。

权限

商户 Owner 拥有全部权限。权限按商户后台的权限点判，各接口标在 x-required-privilege；员工可以同时持有多个角色，权限取并集。标 session 的接口只要求已登录，包括：目标是登录者本人的操作（修改自己的登录密码，即 changePassword 的 type 为 login；改自己的登录邮箱、改自己的显示名、开关自己的收款推送、给自己绑定或解绑微信、查自己的微信绑定结果、看自己的成员信息），读收款通知设置，消息的未读数、公告的列表与详情、把消息标为已读（订单消息列表另须查看支付订单的权限），上传文件，商户列表与切换商户，登记推送令牌与退出登录。权限不足属于业务性拒绝，返回 400，message 写明需要商户后台的哪项权限。

找回密码

商户 App 上不承接找回密码，也不承接登录状态下凭邮箱验证码重置本人的登录密码。现网版本的找回密码入口（/api/v1.0/app/device/forgotPassword/code 与找回流程其余各步），以及 sendPasswordEmailCode、resetPasswordWithEmailCode 的 type 为 login 的请求，不再受理，回 HTTP 400、code 为 208037、顶层 message 为固定的双语提示「暂不支持在 POS / App 上重置密码，请联系 Owner 在商户后台重置 / Password reset is not available on POS / App, please ask your Owner to reset it in the Merchant Portal」。

修改银行账户

商户 App 上不承接修改结算银行账户，改银行账户在商户后台办理。现网版本的修改银行账户提交（POST /api/v1.0/app/device/merchant/bank）不再受理，不看请求内容、权限与仅查看状态，一律回 HTTP 400、code 为 208039、顶层 message 为固定的双语提示「暂不支持在 App 上修改银行账户，请在商户后台修改 / Bank account changes are not available in the App, please update it in the Merchant Portal」。现网 App 的银行信息页对此不显示提示，停留在编辑页。

仅查看状态

商户被设为仅查看时，下列请求返回 400、code 为 208035，查询照常：

  • 收款、退款、释放预授权，账单码的新建与关闭、删除。
  • 改商户的设置与资料：顾客承担手续费、订单有效期、支付方式、收款页设置，商户 Logo、时区、联系方式与地址，登录邮箱（发验证码、提交与确认）。
  • 退款账户充值（含发验证码），通知邮箱的发验证码、添加与删除。
  • 员工的新增、修改、删除，取绑定微信的二维码。
  • 退款密码的修改（changePassword）与重置（sendPasswordEmailCode、resetPasswordWithEmailCode），即 type 为 refund 的那一支。

下列请求照常可用，其余改状态的请求都拦：登录、登记推送令牌、切换商户、修改本人的登录密码（changePassword 的 type 为 login）、开关本人的收款推送、把消息标为已读（含读公告详情）、退出登录，以及上传 Logo 图片（uploadImage，只产生待引用的文件）。

账号密码登录（带滑块验证），同时登记本机

校验滑块票据与账号密码，通过后返回令牌。登录不要求二次验证，账号在商户后台开了验证器的也一样。

username 先按用户名精确匹配，匹配不到再按邮箱，不分大小写。登录所在的商户按登录账号定：Owner 与主商户的员工为主商户，关联商户的员工为其所属的关联商户；这个商户被冻结或删除时登录被拒，不改落其他商户。

这部手机在该商户下还没有登记过时（按 uuid 与 devType 认），登录时顺带登记，返回的 devId 就是它的设备编号；登记过的沿用原来的 devId。这部手机上一次登录得到的令牌随之失效，不论那次登录的是哪个账号、在哪个商户。

下列情形返回 400：

  • 204021 滑块票据没通过校验。
  • 206012 账号不存在或密码不对，两者不区分。
  • 966001 连续登录失败次数过多，账号被锁定。默认连续错 5 次锁 15 分钟（可配置），与商户后台网页登录、POS 登录共用计数。
  • 906004 同一登录名（解析不到账号）短时间内失败过多，稍后再试。默认 15 分钟内 5 次（可配置），与商户后台网页登录、POS 登录共用计数。
  • 208027 账号已被停用。
  • 208029 账号的邮箱还没有验证。
  • 208028 登录所在的商户已被冻结或删除。
  • 108015 这部手机在该商户下的设备已被停用。
  • 108018 本机上报的 uuid 不能用作设备标识（为空，或是运行环境返回的固定占位值）。
  • 缺 uuid、username、password 等必填项。

登记本机的推送令牌

把本机的推送令牌登记到这部手机在当前商户下的设备与当前登录的账号上，之后的收款、退款提醒推到这个令牌。同一个令牌再次登记时（如这部手机换了账号登录，或切换了商户），改记到这一次的账号与设备上；退出登录后停推的令牌，再次登记即恢复推送。推送的语言取本次请求的 Accept-Language，没带时为英文。

  • 找不到设备，或设备不在令牌当前所在的商户名下。
  • devToken 为空。

凭旧密码修改登录密码或退款密码

type 决定改哪一个：

  • login：核对登录者自己的旧登录密码，改为新密码。成功后这部手机保持登录、令牌照常可用；该账号在其他设备与会话上的登录失效，须用新密码重新登录。
  • refund：核对商户的旧退款密码，改为新退款密码。本接口标的 session 只覆盖 login；refund 另须商户后台管理退款密码的权限（account:refund-pin:manage）。

下列情形返回 400：

  • 206011 type 为 login 时旧密码不对。message 里含 Invalid Original Password。
  • type 为 refund 时旧退款密码不对。message 里同样含 Invalid Original Password。
  • 206004 type 为 refund 时旧退款密码连续输错到上限，暂时锁定。
  • type 为 refund 而登录者没有管理退款密码的权限。
  • 208035 type 为 refund 时商户处于仅查看状态，不能改退款密码。login 不受仅查看影响。
  • 新密码与旧密码相同，或不满足对应的密码规则。

忘记退款密码 — 发邮箱验证码

向商户 Owner 的登录邮箱发一封带 6 位验证码的邮件，返回本次的 ticket。重置（resetPasswordWithEmailCode）时带上同样的 type、这个 ticket 与邮件里的验证码。

type 只受理 refund（商户的退款密码）；login 不受理，不看权限一律按总说明「找回密码」返回。

下列情形返回 400，message 写明原因：

  • type 不是上面两个取值。
  • 发得太频繁，还在冷却中。
  • 登录者没有管理退款密码的权限。
  • 208035 商户处于仅查看状态，不能重置退款密码。
  • 208037 type 为 login。

扫顾客的付款码收款

服务端认出付款码的品牌，建订单、向渠道下单，等到渠道的首次应答再返回：付款成功，或渠道在等付款人确认。渠道迟迟不应答时同样返回 order_id。订单的结果以 getTransaction 查到的为准。下单后默认 60 秒内（可配置）没有结果的，订单关闭（getTransaction 的 orderStatus 为 3）。

  • amount 是标价，单位是分。
  • currency 只收商户的结算币种或 CNY。
  • preauth 为 true 时是预授权：付款成功后款项挂起，之后可以释放，与付款码的品牌无关。
  • remark 记为订单备注，查订单时在 remarks 里返回。

同一部手机用同一个付款码、同样的金额、币种与预授权标记的重复请求视为同一笔，返回第一次的结果；首次请求还在处理时到达的重复请求，等首次结果出来后返回同一结果。

下列情形返回 400，message 写明原因：

  • 104500 认不出付款码的品牌。
  • 108502 商户没有开通这个付款码对应的支付方式。
  • 108104 这笔收款不予受理；金额不予受理时落一笔不予受理（1）的订单，响应仍是 400。
  • 108105 算不出这笔收款的手续费。
  • 208035 商户处于仅查看状态，不能收款。
  • 108500 付款码已失效（过期或已被使用）。订单已建立，记为失败。
  • 108501 渠道拒付。订单已建立，记为失败。
  • 107500 承接这个付款码的通道暂时不可用。订单已建立，记为失败。
  • currency 不是商户的结算币种，也不是 CNY。
  • amount 不是正数，或缺 currency、auth_code、amount。
  • 权限不足：需要商户后台「终端收款」的权限。

查订单

按订单号查订单。

payType 为 Credit 时返回订单本身，data 是一个 TransactionDetail；为 Debit 时返回退款详情，路径段是退款号，data 是一个 RefundDetail。两种形状互斥，由 payType 决定。

payType 为 Debit 时，本接口标的 orders:payment:view 之外，另须商户后台查看退款单的权限（orders:refund:view）。

只能查当前商户及其子商户的订单与退款。订单详情的金额是元，十进制字符串（refundFee 除外，见字段说明）；退款详情的 refundFee 是元，数值。时间按商户时区。

退款（请求里带退款密码）

对一笔订单退款，同一个请求里带商户的退款密码。服务端先校验退款密码，再落退款单、提交渠道，拿到渠道的首次应答后返回；返回时退款处理中或已成功。

  • fee 是退款金额，单位是元，服务端四舍五入到分。币种是订单的币种，不传。
  • 可退金额 = 顾客实付总额（金额、小费与顾客承担的手续费之和）− 已退金额。允许部分退、多次退。
  • 商户可用于退款的资金不够时返回 400，见下面的列表。
  • refund_password 是商户的退款密码，全体员工共用。连续输错达到上限（可配置）后锁定一段时间，锁定期内退款密码校验不通过（商户后台、商户 App、POS 都一样）。
  • remark 记为退款备注，查退款详情时在 refundRemark 里返回。
  • 可以退当前商户及其子商户的订单；子商户的订单须运营开了「父商户可退子商户订单」，没开时按订单不存在处理。挂起中的预授权订单（preAuth 为真）不用先释放，可以直接退，部分退也可以；退后订单仍挂起，剩余金额在释放后结算。

data 有两种情形：

  • 退款已受理：返回 refund_id、partner_refund_id、amount、currency、result_code。
  • 命中审核规则（金额达到审核阈值、成交超过退款周期，或当日退款笔数超限）：退款进入审核，不立即退；返回 success（true）与 message，没有 refund_id。审核通过后由服务端完成退款。审核中的退款不计入已退金额，也不出现在退款记录里。

同一部手机对同一订单、同样金额的重复请求在 60 秒内（可配置）视为同一笔，返回这笔退款此刻的结果；首次请求还没建好退款单时到达的重复请求，等建好后返回这笔退款此刻的结果。

下列情形返回 400，message 写明原因：

  • 缺 refund_password，message 为 Refund password is required.。
  • 206003 退款密码不对，message 为 Invalid refund password.。
  • 206004 退款密码连续输错达到上限，暂时锁定，message 里含 password。
  • 208035 商户处于仅查看状态，不能退款。
  • 108025 这笔退款不予受理，不细分原因：订单没有支付成功、已全额退、金额不是正数或超过可退金额、成交超过最大退款期限（可配置）、商户的退款能力被关闭等。
  • 108017 同一登录账号对同一订单在极短时间内重复提交（不论金额）。
  • 908003 同一部手机对同一订单、同样金额在 60 秒内（可配置）再次发起退款，但备注与前一次不同。
  • 权限不足：需要商户后台「发起退款」的权限。
  • 订单不存在，或不在可退的范围内，两者不区分。
  • 商户可用于退款的资金不够这笔退款，message 里含 balance（中文环境含「余额」）。
  • 渠道拒绝退款，message 带渠道给的原因。
  • 缺 fee。

释放预授权

释放一笔挂起中的预授权订单：解除这笔订单的结算锁，不动渠道、不动资金。没有请求体。成功后订单状态仍是 5，preAuth 变为假，之后可以正常退款。挂起中的订单不会到期自动释放。

只能释放当前商户自己的订单，子商户的订单按不存在处理。同一订单在 60 秒内（可配置）的重复释放请求（不论哪台设备）返回第一次的结果；首次请求还在处理时到达的重复请求，等首次结果出来后返回同一结果。之后再释放按「不是挂起中的预授权订单」拒绝。

交易流水，按日分组

返回当前商户及其全部子商户的交易流水，按时间倒序分页，每页的行按营业日分组。

流水的行：

  • 成交的收款，一单一行，时间是成交时刻。
  • 受理的退款（处理中或成功），一笔一行，时间是受理时刻。
  • 未成交、失败、被拒的订单不列；进入审核还没有受理的退款不列。

日期都按商户营业日：begin、end 是营业日，原样匹配，不按设备时区换算；item_key 是行所属的营业日。时间按商户时区。

item_statistics 是这一个营业日里、与列表同范围同条件的收款合计与退款合计，不只是本页的行。同一个营业日的行跨页时，每一页都有这一天的组，item_statistics 相同。

登录者是 role 为 3 的成员（role 的取法见 TerminalRole）时，最早只能查到当前营业日往前 N 天，N 由运营按商户设置，没有设置时不限；不带 begin 或 begin 早于它时，早于的部分不返回，不报错。

下列情形返回 400：

  • begin 或 end 不是合法的 yyyyMMdd 日期。
  • channel、order_status 的取值不认识。
  • 带了 order_id 又带了 begin、end，区间超过上限（默认 31 天，可配置）。
  • 权限不足：需要商户后台查看支付订单的权限。

下载付款收据 PDF

返回一笔订单的付款收据，成功时响应体就是 PDF 文件本身，不套成功响应的外壳。

收据的内容：

  • 抬头：订单所属商户的简称与地址。
  • 时间（付款成功时刻，商户时区，按文字的语言格式化并标明时区）、下单设备（没有设备时写订单来源）、支付方式、订单号。

role 把成员的角色整组换成店长（2）或收银员（3）
nick_name 改显示名
pwd 重置登录密码，须满足密码规则（至少 8 位，含大写字母、小写字母、数字与特殊字符）；该成员所有设备与会话上的登录随之失效
delBinding 为 true 解绑该成员的微信：这个微信不能再登录商户后台，当前商户也不再给它发收款通知

Owner 那一行只能改显示名与解绑微信；登录者不能改自己的角色、不能重置自己的登录密码。

本接口标的 session 覆盖登录者改自己的显示名、解绑自己的微信。登录者不能在这里重置自己的登录密码；改别的成员须有商户后台「成员管理」的权限（account:team:manage）。

下列情形返回 400，message 写明原因：

  • 成员不存在，或不属于当前商户，两者不区分。
  • role 不是 2 或 3；对 Owner 改显示名与解绑微信以外的项；登录者改自己的角色。
  • 登录者重置自己的登录密码，message 提示改用修改密码（changePassword）。
  • pwd 不满足密码规则。
  • 除 account_id 外一项都没带。
  • 206013 要给的角色、或该成员现有的角色超出登录者的权限边界。
  • 208035 商户处于仅查看状态，不能改员工。
  • 权限不足：改别的成员需要商户后台「成员管理」的权限。
