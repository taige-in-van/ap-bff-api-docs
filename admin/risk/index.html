管理后台 风控管理 — 前端契约面 (2.0.1)

Download OpenAPI specification:

管理后台 React SPA 消费的风控管理契约：付款人黑名单的加入、移除与列表，被拒订单的检索、详情与按日计数，商户禁入名单的新增、编辑、解除、列表与详情（含冻结或设为高风险后把商户加入），礼卡客户风险资料的查看与白名单的设与取消。 浏览器持 httpOnly 会话 cookie，字段类型与校验规则以本 spec 各字段为准。

金额口径：金额是对应币种最小单位的整数串，带币种。单笔上限与参与比较的金额是结算币种。

幂等 / CSRF 口径：

  • 加入付款人黑名单、新增禁入名单项、冻结或设为高风险后加入禁入名单带 Idempotency-Key：同一次操作的重试沿用同一个键，重复提交返回首次结果、不会重复执行。
  • 其余写操作按目标值写或带状态前置，不挂幂等键。
  • cookieAuth 的非安全方法一律带 X-CSRF-Token。

可见范围：付款人黑名单、商户禁入名单与礼卡客户是平台级页面，只看功能权限。被拒订单按商户求数据可见范围：范围外商户的被拒订单不出现在列表与计数里，按标识访问一律 404。冻结或设为高风险后加入禁入名单按该商户求数据可见范围。

操作审计：本面的写操作记入操作审计（带操作人、对象、前后状态或前后值）；查询、详情、计数不记。操作人恒为当前登录的后台用户，请求体里没有操作人字段。

加入付款人黑名单

把一个付款人标识加入黑名单，对此后的判定即时生效。同一「类型 + 范围 + 值」只有一项：

  • 没有这一项 → 新建，restored = false。
  • 有、但已移除 → 恢复原项为在用，拉黑原因改为本次所填，仍是同一名单项，restored = true。
  • 有、且在用 → 拒绝（见下），名单不变。

标识的范围：WECHAT / ALIPAY 必填 identifierScope = 该标识所属的应用（appid）；MERCHANT_CUSTOMER 必填 identifierScope = 所选商户的 merchantId（商户客户号只在该商户内有意义，同一客户号在不同商户下是不同的项）；EMAIL 不带范围。邮箱去首尾空白、转小写后存。

标识值长度：邮箱 1–254（须为邮箱格式）、微信与支付宝 1–128、商户客户号 1–100。拉黑原因必填、不能为空白。

幂等基准：Idempotency-Key。同键重复提交返回首次结果、不再新建或恢复。

什么时候拒绝（名单不变）：

  • 308801 同一类型、范围与值已有在用项；context.existingEntryId 带既有项，页面据此定位。
  • 308802 以商户客户号加入时所选商户不存在或已删除。
  • 类型不在枚举、缺范围或邮箱带了范围、邮箱格式不对、值或原因超长、原因为空白 → 400，由 details 定位。

记入操作审计（新建带全部字段；恢复带改前原因与前后状态）。

移除付款人黑名单项

移除一个名单项：只标记为已移除、不删除，对此后的判定即时生效；已被它拒掉的订单仍为被拒。之后同一标识再加入时恢复这一项。

已移除的再移除同样返回 204、不改动、不记审计，重试不会被拒。按目标状态写，不挂幂等键。

什么时候拒绝：名单项不存在 → 404。

被拒订单

被准入拒绝的订单：检索、详情与按日 × 拒绝原因计数。

被拒订单列表

本人数据可见范围内商户的被拒订单，分页，按建单时间从新到旧。日期范围按建单日期，两端必填。

每行带拒绝原因：超单笔上限的带被突破的层、该层当时的上限与当时参与比较的金额（都是结算币种）；付款人在黑名单的带被命中名单项的类型、范围、值、拉黑原因与该项当前状态。归属销售是商户当前的归属销售。

检索都是精确匹配，邮箱不分大小写：付款人标识对订单上的付款人通道侧标识或被命中名单项的值；买家邮箱只对被命中的邮箱类名单项，超单笔上限的被拒订单没有买家邮箱、按买家邮箱检不到。

什么时候拒绝：日期范围缺一端、to 早于 from、跨度超过允许的最大查询窗口、字段格式不对 → 400。

新增禁入名单项

新增一个禁止入驻的主体：名称、原因类别、备注与至少一个标识。新增即时参与入驻审核的比对；来源记为手工录入。

设或取消礼卡客户白名单

把这位付款人的礼卡客户白名单标记设为 whitelisted、备注设为 remark。只改白名单标记与备注，不改礼卡风险等级与累计风险分；从未买过礼卡的付款人也可设。白名单的效果按礼卡风控规则，不在本页定义。

全量覆盖：请求体就是目标本身，remark 不给即清空备注。

已合并的付款人：路径给的付款人已并入另一位付款人时，改的是合并后的那一位，响应的 payerId 是它。

标记与备注都和当前相同时照常成功、不改动、不记审计。按目标值写，不挂幂等键。

什么时候拒绝：

  • 付款人不存在 → 404。
  • remark 超过 256 字或全为空白 → 400。
