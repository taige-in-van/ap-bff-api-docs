管理后台 商户运营管理 — 前端契约面 (2.0.0)

Download OpenAPI specification:

管理后台 React SPA 消费的商户运营契约：商户列表、导出与详情，冻结 / 解冻、关户，代登商户后台，商户成员（新增、停用启用、改角色、删除、解绑微信、解锁、重置 MFA、发重置密码链接）与代改 Owner 登录邮箱，运营资料、资料文件、结算账户与结算周期直改，日切时刻与 KA 等级，商户级设置代配。 浏览器持 httpOnly 会话 cookie，字段类型与校验规则以本 spec 各字段为准。

幂等 / CSRF 口径：

  • 关户、新增成员、新增资料挂 Idempotency-Key：同键同请求体重发返回首次结果；同键改请求体 → 409·908003；首次请求仍在处理 → 409·908002，稍后同键同请求体重发。
  • 置值写（改状态、改角色、改资料、改结算、改日切与 KA 等级、改登录邮箱）与删除不挂；带版本的商户级设置以版本防并发覆盖、不挂；代登、发重置密码链接、取用文件按流程语义不挂；上传每次产生新文件，不挂。
  • cookieAuth 的非安全方法一律带 X-CSRF-Token。

数据可见范围：同管理后台约定「数据可见范围」：列表与导出只含范围内的商户（含本人生效中的临时授权），按标识访问范围外的商户及其成员、文件、设置一律 404。成员接口里的 userId 不是该商户的在册成员 → 404。

操作审计：本面的写操作记入操作审计并带上商户；例外（与现状相同的幂等重放、只发链接或待确认的提交）见各 op。可在该商户详情的操作记录页签查到；列表、详情、文件查看不记。

冻结或解冻商户

全量覆盖：请求体就是目标状态，缺省不代表保持原样。

  • FROZEN：冻结，只对已激活的商户。冻结后的效果由商户状态决定，不逐个改通道开关。
  • ACTIVE：解冻，只对已冻结的商户；通道开关不因解冻改变。

天然幂等的置值写，不挂幂等键：商户已是目标状态时同样返回 204、不改动、不记审计，重试不会被拒。

什么时候拒绝：

  • 308301 商户当前状态既不是目标状态、也不能迁到目标状态（冻结未激活的商户、解冻未激活的商户），重读详情。

代登商户后台

以该商户 Owner 的身份代登商户后台：返回一个一次性、短时效的进入地址 landingUrl，前端新开窗口打开即进入商户后台，当前商户为该商户。地址只能用一次，过期或用过须重新发起。代登会话的规则同管理后台约定「代登会话」。

只有已激活的商户可代登；已冻结的商户不能代登，其资料在商户详情查看。打开进入地址的浏览器若已登录商户后台，须先登出再回来重新发起。每次发起都签一个新地址，不挂幂等键。

什么时候拒绝：

  • 308303 商户不是已激活（未激活或已冻结），或该商户 Owner 已停用、在商户后台无访问资格。

改运营资料（含锁定字段、家庭办公、别名商户码）

只提交要改的字段，一次提交全部生效或全部不生效；能清空的字段传 null 即清空。含商户自己不能改的锁定字段（法定名、经营名、企业类型、注册号、引荐来源、行业、MCC）。字段规则与商户入驻 Business 步相同。改动前后值记入操作审计。

  • merchantCodeAlias：别名商户码，一个商户至多一个、不设到期，与商户码共用同一个命名空间。
  • homeOffice：改为否时，商户须已有至少一张办公室照片。

置值写，不挂幂等键。

什么时候拒绝：

  • 308314 商户未激活：待激活商户的资料在审核中心的代客建档里代补，或由商户在向导修改。

  • 308310 家庭办公改为否、而商户还没有办公室照片：先上传办公室照片。
  • 字段格式或组合不对 → 400，details 定位字段。
