Download OpenAPI specification:

管理后台 React SPA 消费的单商户收单配置契约：通道签约与渠道报备、线上平台标识、受理入口与入口级收窄，商户费率与费率问题清单、计费条款与客户服务费适用范围，商户级收单参数、跨主子退款开关、小票、收款页与小费，店铺码 / 账单 / 链接只读与礼卡卡包模板编号，商户设备与日志、停用启用与释放，开发接入与重置 API 凭证。 浏览器持 httpOnly 会话 cookie，字段类型与校验规则以本 spec 各字段为准。

费率口径：本面的比例费率一律是小数字符串，"0.022" 即 2.2%；固定单笔费是商户结算币种的最小单位整数串（"30" = 0.30），不带币种。录入时比例须大于 0、不超过平台上限，折成百分数至多两位小数（即小数至多 4 位）。

幂等 / CSRF 口径：

  • 加支付方式、提交报备、录入费率、重置 API 凭证挂 Idempotency-Key：同键同请求体重发返回首次结果；同键改请求体 → 409·908003；首次请求仍在处理 → 409·908002，稍后同键同请求体重发。
  • 置值写（改签约、开关入口、收窄、改条款与参数、小票、收款页、小费、卡包模板编号、设备停用启用）与释放设备不挂；带版本或带读到时刻的写以它防并发覆盖、不挂；刷新报备状态按流程语义不挂。
  • cookieAuth 的非安全方法一律带 X-CSRF-Token。

数据可见范围：同管理后台约定「数据可见范围」：按标识访问范围外的商户及其签约、费率、设备等一律 404；费率问题清单只含范围内的商户。

操作审计：本面的写操作记入操作审计并带上商户与前后值，可在该商户详情的操作记录页签查到；读、刷新报备状态、费率问题清单不记。

通道签约

按支付方式的通道签约、子商户号与 MCC、银联 Express、渠道报备与线上平台标识。

通道签约总览（含报备进度与可加的支付方式）

按支付方式列出该商户的签约：所签通道、子商户号、MCC、运营启停与商户自助开关、是否要报备才能拿到子商户号（applicationRequired）、银联 Express（只银联在线有）、已登记的线上平台标识、各类报备的最近一次结果与通道给的拒绝原因。入驻申请提交后由系统建立的签约与报备同样在这里。

availableMethods 列出该商户结算币种下尚未签约、可以加的支付方式，各带可选的通道（每个通道带 applicationRequired，为是的才可填子商户号）与标准费率（没有标准费率的不带）；加支付方式用 createMerchantChannelContract。

加支付方式（新建签约）

为商户新增一个尚未签约的支付方式。通道只能选 availableMethods 里给出的；MCC 可选填；子商户号只有需要报备的通道（候选通道的 applicationRequired 为是）可选填，子商户号按规则生成或不需要子商户号的通道不接受。

费率：填了 feeRate 就按它写一条新费率，从当天起生效，该支付方式的当前费率在新费率的生效首日截断（与录入费率同规则）；不填时，该支付方式已有当前费率的沿用、不另写，没有的取该支付方式在商户结算币种下的标准费率。

子商户号就位即启用：不需要子商户号、或子商户号按规则生成的通道，新建即启用；需要报备的通道，填了子商户号视为已就位、新建即启用且不自动报备，没填的新建为未启用，由系统自动发起报备，首次报备成功、子商户号回写时启用。响应的 enabled 即建成后的启停。

幂等基准：Idempotency-Key。

什么时候拒绝：

  • 308403 该支付方式已有生效签约。
  • 308410 所选通道不能签给该商户（结算币种不符、与已有签约的出款方式不一致，或通道未就绪），重读总览后改选。
  • 308406 填的比例费率超过平台上限，context.capPercentage 是当时的上限（小数）。
  • 308407 该支付方式已排定了未来生效的费率，当天起写入的新费率（所填的或取标准费率的）与之重叠；签约不建，重读费率后再定。
  • 字段格式不对、比例不大于 0 或小数超过 4 位，或给子商户号按规则生成、不需要子商户号的通道填了子商户号 → 400，details 定位字段。

改签约（启停、子商户号、MCC、银联 Express）

只提交要改的字段，并带上读到的 updatedAt；一次提交全部生效或全部不生效。启停不改费率，停用只影响此后的受理。

  • enabled：需要报备的通道在子商户号就位前不能启用；运营录入的子商户号视为就位。
  • subMerchantId：只有需要报备的通道（applicationRequired 为是）上的签约可带；同一通道商户号下该商户的其他签约共用子商户号，录入或修改时一并写入。由空录入为有值即就位，这些签约随之启用（本次同时带了 enabled: false 的除外）；已有子商户号再改值不改启停。null = 清空，这些签约随之停用。
  • mcc：四位 MCC，此后该通道的下单按新值；null = 清空。
  • expressPayEnabled：只银联在线签约可带；签约未启用时开关值保留但不生效。

置值写，不挂幂等键。

什么时候拒绝：

  • 308401 签约在你读取后已被他人改过，签约不变；重读总览再改。
  • 308402 该签约的通道需要报备、子商户号尚未就位，不能启用；待报备成功或先录入子商户号。
  • 308410 要启用，而该签约的出款方式与该商户其他已启用签约不一致。
  • 非银联在线签约带了 expressPayEnabled、不需要报备的通道上的签约带了 subMerchantId、字段格式不对 → 400，details 定位字段。

提交或重提一条渠道报备

对该签约向通道提交报备，内容取商户当前资料。上一次被驳回的同类报备即为重提。通道当场受理即返回，审核结果此后由系统同步，也可用 syncMerchantChannelApplication 按需刷新；首次子商户进件成功时系统回写子商户号并启用签约。

微信 H5 支付权限（applicationType = h5_authorization）另收以下字段，其他报备类型带了 → 400：

  • limitType 限额档，不传按 normal；选 unlimited 时 businessDescription 必填，且须有营业执照。
  • websiteState 网站状态，不传按 launched；选 not_launched 时 websiteHomepageScreenshotFileIds 与 websiteBusinessPageScreenshotFileIds 都必填。
  • 不传 businessLicenseFileId 时取商户入驻证照中的图片件（PNG / JPEG）。
  • 另传的营业执照与网站截图先经 uploadMerchantFile 上传（用途 channel_application_material），再带上传得到的 fileId。

系统自动发起的 H5 申请是普通限额、已上线、不带材料；被驳回后在这里补改材料重提，仍是同一条报备。重提时档位与材料以本次请求为准整体改写、不与上次合并：先用 ChannelApplication 回读的上次提交内容预填，改好要改的再整份提交。

幂等基准：Idempotency-Key。

什么时候拒绝：

  • 308415 H5 申请的档位与材料不齐：选了无限额而缺营业执照或业务说明（没传营业执照时先取商户入驻证照中的图片件，仍无才拒），或选了未上线而缺网站首页或业务页截图。details 指到缺的字段，不向通道提交。
  • 308416 带的 fileId 不可用于这里（不存在、不是本商户上传的，或用途不是 channel_application_material）。details 指到该字段，重新上传后再带。
  • 308404 同签约同类报备还在审，不能再提；刷新状态后再定。
  • 308405 通道当场拒绝，context.channelErrorCode / context.channelErrorMessage 是通道给的原因（通道给了才带）；改资料后重提。
  • 该签约的通道不适用这类报备 → 400。
