管理后台 商户入驻审批与合规 — 前端契约面 (2.1.0)

Download OpenAPI specification:

管理后台 React SPA 消费的审核中心与代客建档契约：四类申请（入驻、受理模式开通、插件入口开通、结算信息变更）的审核队列、详情、文件取用与决定，通过入驻申请前的禁入名单比对与持权限跳过；代客建档的检查、建档、逐步填资料（含议价条款）、上传、生成合同并发确认链接、代补料后代提交、撤回；线上平台标识补录待办。 浏览器持 httpOnly 会话 cookie，字段类型与校验规则以本 spec 各字段为准。

幂等 / CSRF 口径：

  • 代客建档、发起确认挂 Idempotency-Key：同键同请求体重发返回首次结果；同键改请求体 → 409·908003；首次请求仍在处理 → 409·908002，稍后同键同请求体重发。
  • 决定、跳过通过、代提交、撤回带状态前置，同一申请重复提交时后到者按状态不符拒绝，不挂幂等键；逐步保存是置值写，不挂；上传每次产生新文件，不挂。
  • cookieAuth 的非安全方法一律带 X-CSRF-Token。

数据可见范围：按商户组织，同管理后台约定「数据可见范围」：列表只含范围内商户的申请，按标识访问范围外商户的申请返回 404。

文件：申请详情不带文件地址；要看某个文件时调 createApplicationFileAccessUrl 现签一个短时效地址，过期后再签。

申请详情

一张申请的全部审核资料，按申请类型返回对应部分：

  • 入驻申请：steps（入驻五步的资料，文档位只给文件引用、不给访问地址）；代客建档的另带议价条款 steps.terms 与 signatureRequests（每次发起确认的记录）。
  • 结算信息变更：settlementChange（新旧对比，账号只给末 4 位掩码）。
  • 受理模式开通：acceptanceMode 与 paymentMethods。
  • 插件入口开通：entryPoint 与 storeUrl；改店铺网址触发的复审也是这一类。

blocklistHits 是本次读取时与禁入名单比对的命中项（仅入驻申请比对，无命中为空数组）；history 按时间列出每次提交、决定与代客建档的操作。查看不进操作审计。

决定申请（通过、拒绝或要求补料）

对审核中的申请下决定：

  • APPROVED：通过。入驻申请通过即商户激活，同一次完成；结算信息变更通过即新账户生效、新周期随后生效；开通申请通过后，入口能否使用由通道进件与产品配置后续置位决定。入驻申请通过前与禁入名单比对，命中即拒绝。
  • REJECTED：拒绝，remark 必填，作为拒绝说明。结算信息变更被拒，旧值保留。
  • MORE_INFO_REQUIRED：要求补料，只用于入驻申请；missingFields 至少一项，不带原因、不给商户发邮件。

通过不改 Owner 的凭据，任何通知都不带明文凭据。两人同时决定以先到者为准。带状态前置，不挂幂等键。

什么时候拒绝：

  • 308201 申请已不在审核中（他人先决定过，或已撤回），重读详情。
  • 308202 入驻申请禁入名单命中，context.blocklistHits 列出命中项；持跳过权限的改走 approveApplicationOverridingBlocklist。
  • 304201 对非入驻申请要求补料。
  • 拒绝没填说明、要求补料没给待补项 → 400。

跳过禁入名单通过入驻申请

禁入名单命中时，填写跳过理由后通过入驻申请：效果与 decideApplication 的通过相同，只是比对命中也照常通过。除跳过禁入名单的权限外，另须持通过申请的权限。跳过理由与命中项记入操作审计。带状态前置，不挂幂等键。

什么时候拒绝：

  • 308201 申请已不在审核中，重读详情。
  • 304201 不是入驻申请。
  • 没填理由 → 400。
  • 当前比对没有命中 → 400，改走普通通过（decideApplication）。

代客建档

代客建档：检查、建档、逐步填资料、上传、发起确认、代提交、撤回（按使用顺序排列）。

代客建档（建出待激活商户与草稿申请）

录入 Owner 联系人、所属机构、归属 BD 与商户语言，建出一个待激活的商户与一张入驻申请草稿（DRAFT），开户来源为管理后台。之后逐步填资料（updateAssistedApplicationStep）、上传文件、发起确认。

  • Owner 邮箱不属任何平台用户：同时建出该 Owner 的账号，此时还没有密码；审核通过后 Owner 凭开户邮件设密。
  • Owner 邮箱已属平台用户，且该用户是某家商户的 Owner、或在商户后台没有身份：新商户挂在该用户名下，不另建账号、不动其密码，响应 ownerIdentity = existing。
  • 建档不给商户发任何邮件。
  • 同名存量商户与禁入名单不拦建档，建档前用 checkAssistedOnboarding 提示。

幂等基准：Idempotency-Key。

什么时候拒绝：

  • 308205 Owner 邮箱的已有账号不能成为 Owner：是其他商户的员工，或待验证、已停用；不建任何记录。
  • 机构或 BD 不存在、字段格式不对 → 400。

建档前检查（Owner 账号、同名商户、禁入名单）

建档前的只读检查，不建任何记录、不进操作审计。用 POST 承载是为了不把邮箱放进地址。

  • ownerIdentity：new 该邮箱不属任何平台用户，建档会同时建出 Owner 账号；existing 已属平台用户，且该用户是某家商户的 Owner、或在商户后台没有身份，新商户会挂在该用户名下；unusable 已属其他商户的员工，或待验证、已停用的账号，不能建档。
  • sameNameMerchants：法定名相同或注册号相同的存量商户（只给商户码与名称，可能在本人数据范围外），供核对，不拦建档。
  • blocklistHits：与禁入名单比对的命中项，只提示，不拦建档。

不挂幂等键。

代客建档：保存一步资料

保存代客建档申请的一步资料，申请须为草稿或待补料。请求体恰含一个步骤键，且须与路径的 {step} 一致；各步字段规则同商户自己填入驻向导时的那一步。保存只校验已填字段的格式、不要求本步填齐，资料是否齐全在发起确认与代提交时统一校验。

  • documents：按文档位绑定上传得到的 fileId，未传的文档位保持原绑定，传 null 移除。
  • terms：议价条款，只代客建档的入驻申请有。按支付方式（含插件入口专用行）的比例费率、固定单笔费与固定费免收截止日，外加手续费结算模式；整组置换。比例费率是小数字符串（"0.022" = 2.2%），须大于 0、不超过平台上限，至多 4 位小数（折成百分数至多两位小数）；固定单笔费是结算币种的最小单位整数串。条款随申请进合同，商户签署、申请提交后按它建立该商户的费率与结算模式。
  • 有未签的确认请求时，任何改动都使它作废（链接失效），须重新发起确认、按改后资料重新生成合同；已签的确认只在改到签署关键字段（议价条款、结算账户、法定名、注册号）时作废，须重新发起确认、Owner 重签。作废时响应 signatureInvalidated = true。

置值写，不挂幂等键。

什么时候拒绝：

  • 308201 申请不在草稿或待补料（已提交审核、已决定或已撤回），重读详情。
  • 308204 不是代客建档的申请。
  • 304202 字段格式或长度不对、不在候选内；details 每项的 field 是字段路径（如 settlement.bankAccount.accountNumber），前端在对应字段旁提示。
  • 304204 结算周期不在当前候选档位内，重取结算配置后重选。
  • 308206 文档位引用的文件不可用，details 指到 documents.<docKey>，重新上传后再绑定。
  • 308406 条款里的比例费率超过平台上限，context.capPercentage 是当时的上限（小数）。
