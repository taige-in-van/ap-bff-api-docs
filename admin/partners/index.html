管理后台 机构与分润 — 前端契约面 (2.0.0)

Download OpenAPI specification:

管理后台 React SPA 消费的机构与分润契约：机构与两层上下级、启停，机构分润方案与成本率，平台提成矩阵与提成规则，按生效日改派商户的归属销售与整机构改派，提成报表与员工提成的查看与导出，后台账号的推荐码。 浏览器持 httpOnly 会话 cookie，字段类型与校验规则以本 spec 各字段为准。

金额与比例口径：金额是对应币种最小单位的整数串，带币种；不同结算币种的金额分别合计，不跨币种相加。比例是小数串，最多六位小数（0.006 = 0.6%）。交易月与生效月是 YYYY-MM，按字面值收发。

幂等 / CSRF 口径：

  • 新建机构、整机构改派带 Idempotency-Key：同一次操作的重试沿用同一个键，重复提交不会重复执行。
  • 其余写操作按目标值写，同值重提不改动，不挂幂等键。
  • 导出按读处理，不挂幂等键。
  • cookieAuth 的非安全方法一律带 X-CSRF-Token。

可见范围：机构、分润方案、提成矩阵与提成规则是平台级页面，只看功能权限。改派按商户（单户）或源机构（整机构）求数据可见范围。提成报表按主体收口：数据范围为本人名下商户的只看主体为本人的 BD 报表；为所属机构的只看主体为所属机构及其直接下级机构的机构报表；全部商户的看全部。员工提成按员工收口：本人名下商户只看本人；所属机构只看所属组织为所属机构及其直接下级机构的员工；全部商户看全部。跨范围临时授权不作用于两者。他人推荐码按账号的所属机构收口。范围外的对象不出现在列表、合计与导出里，按标识访问一律 404。

操作审计：本面的写操作记入操作审计（带操作人、对象、前后状态或前后值）；查询、详情、导出不记。操作人恒为当前登录的后台用户，请求体里没有操作人字段。

新建机构

新建一个机构。只有机构名称必填；不传 commissionEnabled = 计算分润。新机构为启用中。机构名称不要求唯一。

建成后可随即邀请该机构的首个机构账号：另调 staff 契约的 createStaff（数据范围 partner、partnerId 为新机构）。两次调用互相独立，邀请失败时机构保留，之后在后台账号处以该机构为所属机构再邀请；邀请另需建号权限，没有时只建机构。

幂等基准：Idempotency-Key。

什么时候拒绝（不建）：

  • 308754 所选上级机构不可选：不存在、已停用，或本身已有上级（只两层）。
  • 名称缺失、字段超长、邮箱格式不对 → 400。

记入操作审计。

编辑机构

整体替换机构资料、上级机构与是否计算分润，字段规则同 createPartner；不传的选填字段 = 清空，不传 parentPartnerId = 清空上级（成为一级机构）。

  • 改「是否计算分润」自改值当月起生效，之前的月份（含之后被重算的）仍按当时的值；同一个月内多次改值以最后一次为准；改值本身不触发重算。
  • 改上级即改上级机构的机构账号看得到的商户范围。

什么时候拒绝（机构不变）：

  • 308754 上级机构不可选：不存在、已停用、本身已有上级、就是本机构，或本机构已有下级机构（只两层）。只在新设或更换上级时判；parentPartnerId 与现值相同时不判，上级已停用的机构照常可改其他资料。
  • 名称缺失、commissionEnabled 缺失、字段超长、邮箱格式不对 → 400。

按目标值写，不挂幂等键。有改动时记入操作审计（带改动字段的前后值）。

设机构分润方案

从 effectiveFromMonth 的月初起生效一份新方案，截止当前最新方案。与最新方案同月即替换它。

  • 差价方案（SPREAD）必带保留比例 commissionPct（大于 0、不大于 1），可带按支付方式 × 入口的成本率（不小于 0、小于 1，同一支付方式 × 入口只一条；未配的支付方式不计提）。
  • 提成矩阵（MATRIX）与上浮（UPLIFT）方案不带保留比例与成本率。
  • 支付方式与入口只能取平台目录里的值。

什么时候拒绝（不生效）：

  • 308755 生效月不被允许：早于提交时所在月的上一个月，或早于当前最新方案的起始月。context.earliestAllowedMonth 带最早可用的生效月，页面据此回填。
  • 308756 成本率的支付方式不在平台目录里。
  • 差价方案缺保留比例、非差价方案带了保留比例或成本率、比例越界、成本率重复、入口不是可选值 → 400。

同月重提 = 替换、结果相同，不挂幂等键。记入操作审计（带新方案与被截止方案的内容）。
