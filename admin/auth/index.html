管理后台 登录与个人设置 — 前端契约面 (2.2.1)

Download OpenAPI specification:

管理后台 React SPA 消费的登录与个人设置契约：登录与会话（密码 + 人机校验 + 动态码、首次登录内绑定验证器、受信浏览器、企业微信扫码、当前会话、登出）、忘记密码、邮件链接落地页（受邀设密、确认新登录邮箱），以及本人资料、改密、重绑验证器、企业微信绑定与本人登录 IP 白名单。 浏览器持 httpOnly 会话 cookie（登录后 set-cookie），字段类型与校验规则以本 spec 各字段为准。

幂等 / CSRF 口径：

  • 认证类（登录、动态码、扫码、登出）与多步挑战类（找回密码、邮件链接、重绑验证器）按流程语义不挂 Idempotency-Key；改密挂；天然幂等的改资料、改白名单、解绑不挂。
  • cookieAuth 的非安全方法一律带 X-CSRF-Token；公开端点（security: []）无会话、不带。

登录与会话

登录与会话：密码登录、动态码步（含首次绑定验证器）、企业微信扫码登录、当前会话、登出。

密码登录（登录名 + 密码 + 人机校验；转动态码步，受信浏览器直接建会话）

登录名 + 密码，人机校验开启时另带人机校验结果。管理后台账号每次登录都要过动态码步，结果按 status 分：

  • ESTABLISHED：本浏览器在受信有效期内，免动态码，已 set-cookie 建会话。
  • MFA_REQUIRED：去动态码步，把 mfaChallenge 与验证器上的 6 位码提交到 completeMfaChallenge。
  • MFA_ENROLLMENT_REQUIRED：账号还没绑定验证器（新账号或验证器被重置），先用 mfaEnrollment 在验证器里添加，再把 mfaChallenge 与验证器上的码提交到 completeMfaChallenge；绑定完成前不建会话，也不能使用其他功能。

受信浏览器凭据由服务端存在 HttpOnly cookie 里，前端不读不写；凭据已失效（过期、被撤销）时本接口照常返回 MFA_REQUIRED，前端不必区分。

什么时候拒绝：

  • 304002 人机校验开启而没带结果，或校验未通过；不校验密码。
  • 306001 登录失败：登录名不存在、密码错、账号停用、没有管理后台访问资格，一律此码、不区分。
  • 306010 密码对了但来源 IP 不在本人登录 IP 白名单：明确提示当前网络不允许登录，回第一步；不进动态码步。
  • 966001 账号因连续登录失败被锁，等冷却。

不挂幂等键（认证类）。各情形的页面处理见 flows。

动态码步（含首次绑定验证器；通过即建会话）

提交 login 或 pollWechatLogin 给出的 mfaChallenge 与验证器上的 6 位码，通过即建会话，status 恒为 ESTABLISHED。挑战是首次绑定时，码对即完成绑定。

勾选 trustBrowser 时本浏览器同时成为受信浏览器：有效期内在本浏览器登录免动态码，其余校验照常。本人改密、被重置密码、被重置验证器时，该账号的受信浏览器全部失效。

什么时候拒绝：

  • 306001 动态码错，留在动态码步重输（同一 mfaChallenge 仍可用）。
  • 306002 挑战已过期、已用或已作废，回登录页第一步重新登录。
  • 966001 账号因连续登录失败被锁。

不挂幂等键（认证类）。

企业微信扫码登录 — 轮询（确认后进动态码步）

轮询扫码登录结果，恒返回 200。扫码后先检查能否登录，不通过的在企业微信里直接告知扫码人原因、不出确认按钮；确认后再过动态码步（受信浏览器免动态码）：

  • WAITING：二维码还没被扫，继续轮询。扫码人那边临时出错、提示稍后再试时也回到它，同一张二维码可以直接重扫。
  • SCANNED：已扫码、等用户在手机上确认，继续轮询；页面显示「扫码成功，请在手机上确认」。扫码后检查未通过也表现为它，不返回原因，直到二维码过期。
  • EXPIRED：终态，重新发起。含二维码过期、票据非法、扫码人在企业微信里取消。
  • REJECTED：终态，登录失败（确认后访问资格已失效）；提示与密码登录失败相同的文案，重新发起。
  • MFA_REQUIRED / MFA_ENROLLMENT_REQUIRED：确认成功，去动态码步，形状与处理同 login 的同名状态；动态码步完成前再轮询，返回同一个 mfaChallenge。
  • ESTABLISHED：本浏览器受信，免动态码，已 set-cookie。

未知值按 WAITING 处理。

忘记密码

忘记密码自助重置：邮箱登录名收邮件验证码、用户名登录名用验证器码；重置不改验证器绑定。

找回密码 — 发起（恒 202，不暴露账号是否存在）

按 loginId 的形态选验证方式：

  • 是合法邮箱格式的按邮箱账号：账号存在则往该邮箱发 6 位验证码。
  • 否则按用户名账号：用验证器里的 6 位码，不发邮件。

恒返 202，账号存在与否响应一致。重发 = 冷却结束后再调本接口，得到新 challengeId，旧码作废。429 为端点 / IP 级限流。

找回密码 — 验证码 + 新密码一次提交

验证码与新密码一次提交：码正确才改密，该账号全平台会话失效、受信浏览器全部失效，本人登录邮箱收到密码已修改通知（用户名账号不发）。只改密码、不改验证器绑定，下次登录仍要过动态码步。

不挂幂等键（挑战类）。挑战已被消费后再提交返回 306002。

什么时候拒绝：

  • 304001 验证码错，次数未超限，可重输（新密码无需重填）。
  • 306002 挑战已过期、已作废或已被消费，须重新发起。
  • 306003 错码次数超限，挑战作废，须重新发起。
  • 新密码不满足密码规则 → 400。
error-codes: [304001,306002,306003]

受邀设密

受邀的后台用户在邀请链接落地页设置登录密码；不建会话。

受邀设密（邀请链接落地页提交；不建会话）

校验邀请链接里的一次性令牌，写入登录密码并激活账号，登录邮箱同时标为已验证。不建会话：设密成功后回登录页，用新密码登录，首次登录内绑定验证器。

邀请链接形如 /invite/set-password#token=…&email=…：页面从地址的 fragment 取令牌和被邀请的邮箱，邮箱只供页面展示，提交以令牌为准。令牌只在设密成功时消费，之前失败的可用同一令牌重试。

什么时候拒绝：

  • 306005 令牌无效或已过期（含被重发作废），请管理员重发邀请。
  • 306006 令牌已用过、账号已激活，去登录页登录；本次提交的新密码未生效。
  • 新密码不满足密码规则 → 400。

确认新登录邮箱

管理员改了后台账号的登录邮箱后，当事人在新邮箱收到的确认链接落地页；不建会话。

确认新登录邮箱（邮件链接落地页提交；不建会话）

管理员改了已激活账号的登录邮箱后，新邮箱收到确认链接；当事人在落地页主动提交后才切换为新邮箱，确认前旧邮箱仍可登录、新邮箱不可登录。令牌一次性，打开页面不消费。切换不影响已有会话。

链接形如 /confirm-login-email#token=…：页面从地址的 fragment 取令牌，提交时放请求体。

什么时候拒绝：

  • 306002 链接无效、已过期或已被新的一次改动顶掉。
  • 968001 确认前新邮箱已被别的账号使用，这次改动作废，请管理员换一个邮箱重改。
