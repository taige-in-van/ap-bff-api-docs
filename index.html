BFF API 契约

前端、收银台、终端（POS / 商户 App）与微信确认页消费的 REST 契约,按 consumer / module 分目录。

⚠️ design / review 阶段契约 —— 实现前可能调整;可据此并行开发,勿当冻结契约。

契约版本:stage/261027-slice-g-devices · 联调环境按 部署

⚠️ 本页契约与联调环境部署所依据的版本不同:接口以各调用时序页的就绪标识为准(⚠️ 表示该接口契约在实现之后有改动)。

🧪 调用时序页的接口表带联调就绪标识:✅ 已部署到联调环境、可对接调试;⚠️ 契约在实现之后有改动、待后端重验;无标识 = 尚未部署。下方调用时序列表里页面名后的 ✅ = 该页接口全部 ✅。

🔌 联调指南（dev-env.html） —— 联调环境地址、本地代理、CSRF、测试账号与数据重置说明，后端随环境变化更新。

📐 API 基础约定（商户后台先读） —— 错误体 / 分页 / 幂等 / CSRF / 状态码 / 时间金额，商户后台各模块共用；收银台的跨接口约定（会话、调用顺序、金额、错误）写在其契约顶部说明里；终端面（POS / 商户 App）同样，凭据、响应外壳与状态码写在各自契约顶部。
🔢 error-codes.json（终端面另见 terminal/error-codes.json）—— 错误码表（每个 code 的含义〔name，可当 i18n key〕/ 对应 HTTP 状态 / 能否重试 / 必带 context 字段；「该怎么处理」不在表里，看返回它的那个接口的说明），非 2xx 一律按 code 分流。
